## 手順（ユーザー操作）
1. ブラウザで Microsoft Entra 管理センター（entra.microsoft.com）または Azure ポータルを開き、`masakaken.shared01@outlook.jp` でサインインする。
2. 「アプリの登録」→「新規登録」。
   - 名前：`JDRT-Monitor-Mail`（任意）
   - サポートされているアカウントの種類：**個人用 Microsoft アカウントのみ**
   - リダイレクト URI：空のまま
3. 登録後、概要の **アプリケーション（クライアント）ID** を控える。これは秘密ではないが、**ソース・文書・Git には書かない**。
4. 「認証」→「詳細設定」→ **パブリック クライアント フローを許可する：はい** にして保存。
5. 「API のアクセス許可」で Microsoft Graph の委任アクセス許可 `Mail.Send` があることを確認する（個人アカウントでは初回サインイン時の同意で付与される）。

## 学校PCでの設定（ユーザー操作）
1. クライアント ID を、学校PCの**ユーザー環境変数** `JDRT_MAIL_CLIENT_ID` に設定する（Git 管理外）。`config.json` の `mail_client_id` でも読めるが、環境変数を推奨する。
2. サインイン（初回だけ）：
   ```
   04_プログラム\venv\Scripts\python.exe 07_監視システム\graph_mail.py signin
   ```
   表示された URL を開き、表示されたコードを入力して、`masakaken.shared01@outlook.jp` で同意する。
3. 以後、トークンは `~/.jdrt-monitor/<hash>/mail_token.bin` に Windows の DPAPI（現在のユーザー）で暗号化して保存される。別ユーザー・別PCでは復号できず、その場合は再サインインが必要になる。
4. 有効化する設定キー（`config.json`、ユーザー判断）：`mail_enabled: true`（キュー投入）、`expected_completed_targets`（SP-06 で確定する整数）、`mail_to`（宛先。送信ワーカー実装時に使う）。

## 失敗時の見方
| 症状 | 意味 | 対応 |
|---|---|---|
| サインインでコードが期限切れ | device code の有効期限（約15分） | もう一度 `signin` |
| `auth_expired` でキューが止まる | 再サインインが必要 | `signin` 後に `resume_after_signin` |
| `uncertain_preserved` | 送信の受付が不明（応答喪失など） | 自動再送しない。受信箱を確認してユーザーが判断 |
| `failed_preserved` | 通信断を規定回数再試行して失敗、または 400/403 など | 保全。原因確認後にユーザーが判断 |


## 運用上の注意（独立レビュー対応、2026-11-07）

- **メールを送るのは `mail_worker.py` だけ。** 監視（`watch.py`）はキューに入れない（二重投入の競合を避けるため）。ワーカーが `mail_enabled: true` のとき、events を見て異常停止と全完了だけをキューに入れて送る。
- **過去のイベントを一斉送信しない：** `mail_enabled` を有効にすると、それまでに溜まった通知対象イベントがすべて送られる。避けるには、config に `mail_enabled_since`（ISO 8601 UTC、例 `2026-11-07T00:00:00+00:00`）を入れる。それより古いイベントは送らない。
- **outbox（`<runtime>\outbox\*.json`）のファイルを消すと、そのイベントはもう一度キューに入って再送される。** 送信済みの記録を手で消さない。
- **再試行：** 通信できないときは最大48時間、間隔は最大1時間で再試行する。それでも送れなかったものは `failed_preserved`（未送信が確定）になり、`python mail_worker.py resume-unsent` で戻せる。**受付不明（`uncertain_preserved`）は戻せない。** 受信箱と迷惑メールを確認して、ユーザーが判断する（再送は二重送信のおそれ）。
- **サインインが切れたとき：** `auth_expired` になる。`graph_mail.py signin` の後、`python mail_worker.py resume`。ワーカーは1日1回トークンを更新して、更新トークンが使われないまま失効するのを防ぐ。
- **異常に気づく手段：** メールが止まる状態（`auth_expired`・`uncertain_preserved`・`failed_preserved`）になると、Windows のトーストが出て、`status.html` と `watch.py status` のメール欄に件数が出る。これはメールではなくローカル通知。
- **全完了の通知は、親ループ（`choice_parent_loop.py`）が出す。** 監視の `expected_completed_targets` は、既定で未設定のまま。設定する場合も、数えるのは `purpose=core` かつ `runs/` 配下の研究セルだけ（smoke・技術試験・native build は数えない）。
