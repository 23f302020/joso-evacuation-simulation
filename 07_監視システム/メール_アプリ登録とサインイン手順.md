# メール通知：アプリ登録とサインイン手順（SP-04）

> **この手順はユーザー本人の操作が必要。** 私（エージェント）は、アプリ登録・サインイン・同意・パスワードや認証コードの入力を代行しない。実メール送信も、ユーザーが明示的に許可するまで行わない。

## 目的
学校PCの監視から `masakaken.shared01@outlook.jp` 経由で結果メールを送る。送信は Microsoft Graph の `sendMail`（委任権限 `Mail.Send` と `offline_access`）。コードは `07_監視システム/graph_mail.py`（標準ライブラリのみ。追加インストール不要）。

## 料金と中止条件
- アプリ登録そのものは無料の見込み。Graph の `sendMail` に呼び出し課金はない（要・画面で確認）。
- **カード番号・支払い方法・「Azure 無料アカウントの作成」を求められたら、そこで中止して私に知らせる。** アプリ登録だけならそれらは不要のはず。
- 「ディレクトリがない」「テナントがない」旨のエラーが出たら、そこで中止して私に知らせる（無料のディレクトリ作成で済むかは未確認。代案は SMTP など）。

## 手順（ユーザー操作）
1. ブラウザで Microsoft Entra 管理センター（entra.microsoft.com）または Azure ポータルを開き、`masakaken.shared01@outlook.jp` でサインインする。
2. 「アプリの登録」→「新規登録」。
   - 名前：`JDRT-Monitor-Mail`（任意）
   - サポートされているアカウントの種類：**個人用 Microsoft アカウントのみ**
   - リダイレクト URI：空のまま
3. 登録後、概要の **アプリケーション（クライアント）ID** を控える。これは秘密ではないが、**ソース・文書・Git には書かない**。
4. 「認証」→「詳細設定」→ **パブリック クライアント フローを許可する：はい** にして保存。
5. 「API のアクセス許可」で Microsoft Graph の委任アクセス許可 `Mail.Send` があることを確認する（個人アカウントでは初回サインイン時の同意で付与される）。

## 学校PCでの設定（ユーザー操作）
1. クライアント ID を、学校PCの**ユーザー環境変数** `JDRT_MAIL_CLIENT_ID` に設定する（Git 管理外）。`config.json` の `mail_client_id` でも読めるが、環境変数を推奨する。
2. サインイン（初回だけ）：
   ```
   04_プログラム\venv\Scripts\python.exe 07_監視システム\graph_mail.py signin
   ```
   表示された URL を開き、表示されたコードを入力して、`masakaken.shared01@outlook.jp` で同意する。
3. 以後、トークンは `~/.jdrt-monitor/<hash>/mail_token.bin` に Windows の DPAPI（現在のユーザー）で暗号化して保存される。別ユーザー・別PCでは復号できず、その場合は再サインインが必要になる。
4. 有効化する設定キー（`config.json`、ユーザー判断）：`mail_enabled: true`（キュー投入）、`expected_completed_targets`（SP-06 で確定する整数）、`mail_to`（宛先。送信ワーカー実装時に使う）。

## 未実装・未実施（明示）
- **実メール送信は未実施。** 送信器の動作は偽のHTTP応答で試験済み（`test_graph_mail.py` 17件）だが、実サーバーとの接続は未確認。
- **送信ワーカー `mail_worker.py` は実装・試験済み（偽の送信器のみ）。常駐タスクとしての登録と実起動は未実施。** サインイン後に `python mail_worker.py run`（常駐）、再サインイン後は `python mail_worker.py resume`。`config.json` の `mail_enabled: true` と `mail_to`（宛先）が必要。
- 試験メールを送る場合は、件名・本文・宛先をユーザーが確認してから行う。

## 失敗時の見方
| 症状 | 意味 | 対応 |
|---|---|---|
| サインインでコードが期限切れ | device code の有効期限（約15分） | もう一度 `signin` |
| `auth_expired` でキューが止まる | 再サインインが必要 | `signin` 後に `resume_after_signin` |
| `uncertain_preserved` | 送信の受付が不明（応答喪失など） | 自動再送しない。受信箱を確認してユーザーが判断 |
| `failed_preserved` | 通信断を規定回数再試行して失敗、または 400/403 など | 保全。原因確認後にユーザーが判断 |
