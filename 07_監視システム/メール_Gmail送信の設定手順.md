# メール通知：Gmail（SMTP）での送信設定（SP-23）

> **この手順はユーザー本人の操作が必要。** 私（エージェント）は、アカウント作成・2段階認証・アプリパスワードの発行と入力・同意を代行しない。実メール送信も、ユーザーが件名・本文・宛先を確認して許可するまで行わない。

## 経緯
Microsoft の個人アカウントは、Azure/Entra のポータルに入れず（`AADSTS16000`：個人アカウントにはテナントが無い）、アプリ登録ができなかった。Outlook.com の SMTP は基本認証（アプリパスワード）が使えない（Q&Aに複数の報告）。Azure の無料アカウントはカード登録が要る。そのため、**送信元を Gmail（SMTP＋アプリパスワード）に変更した**（ユーザー判断、2026-11-12）。コードは `07_監視システム/smtp_mail.py`。送信器だけが変わり、キュー・再送防止・ワーカーは同じ。

## 方針
- **送信専用の新しい Gmail アカウントを使う。** アプリパスワードは、そのアカウントのメールに広い権限を持つ（Mail.Send だけの権限より強い）。**個人の Gmail は使わない。**
- パスワードは、チャット・文書・Git・ログに出さない。学校PCに、Windows の DPAPI（現在のユーザー）で暗号化して保存する。

## A. 送信専用 Gmail の作成（ユーザー操作。スマホのモバイル回線を推奨）
1. `https://accounts.google.com/signup` で、新しい Google アカウントを作る（**正しい生年月日**を入れる。電話番号の確認を求められることがある）。
2. 2段階認証を有効にする：`https://myaccount.google.com/security` →「2段階認証プロセス」。**Google の公式ページによると、アプリパスワードには2段階認証が必須。**
3. アプリパスワードを発行する：`https://myaccount.google.com/apppasswords`。名前は `JDRT`（任意）。**16文字のパスワードは一度しか表示されない。** 控えるが、チャットには貼らない。
   - 項目が出ない場合：2段階認証が「セキュリティキーのみ」になっている、組織（学校・職場）のアカウント、「高度な保護」のアカウントでは、出ないことがある。その場合は、私に画面の文言を教える。

## B. 学校PCでの設定（ユーザー操作。`<ROOT>` は配置先）
1. **通信の確認**（変更なし。結果を教えてください）：

```powershell
Test-NetConnection smtp.gmail.com -Port 465 -InformationLevel Quiet
```

`False` の場合、学校のネットワークが 465 番を止めている可能性がある（現在の実装は 465 番のみ。587 番＝STARTTLS は未実装）。

2. **config.json に追記する**（`<ROOT>\07_監視システム\config.json`。パスワードは入れない）：
   - `"mail_provider": "gmail_smtp"`
   - `"mail_sender": "<送信専用GmailのアドレスA>"`
   - `"mail_to": "<通知を受け取る学校のメールアドレス>"`
   - `"mail_enabled": true`
   - `"mail_enabled_since": "<有効にする時刻のISO8601 UTC。例 2026-11-12T00:00:00+00:00>"`（過去のイベントの一斉送信を防ぐ）
3. **アプリパスワードを保存する**（入力は画面に表示されない）：

```powershell
<ROOT>\04_プログラム\venv\Scripts\python.exe -B -X utf8 <ROOT>\07_監視システム\smtp_mail.py setup
```

`saved (Windows DPAPI, current user)` と出れば成功。保存先は `~\.jdrt-monitor\<識別子>\smtp_secret.bin`（暗号化）。
4. **ワーカーを起動する**（試験メールを送る前に、件名・本文・宛先をユーザーが確認する）：

```powershell
<ROOT>\04_プログラム\venv\Scripts\python.exe -B -X utf8 <ROOT>\07_監視システム\mail_worker.py run
```

## 運用上の注意
- **Google アカウントのパスワードを変えると、アプリパスワードがすべて失効する。** 送信は `auth_expired` で止まり、トースト通知が出る。新しいアプリパスワードを発行して `smtp_mail.py setup` をやり直し、`python mail_worker.py resume` で再開する。
- 受付不明（`uncertain_preserved`）は再送しない。受信箱と迷惑メールを確認して、ユーザーが判断する。
- 宛先の学校のメールが、新しい Gmail からの通知を迷惑メールに振り分けないかは、試験送信で確認する。
- Gmail の送信には1日あたりの上限がある（個人アカウントで数百通程度）。完了通知・異常通知なら足りる。
- 既存の「メール_アプリ登録とサインイン手順.md」（Graph）は、プロバイダを `graph` に戻す場合の記録として残す。

## 失敗時の見方
| 症状 | 意味 | 対応 |
|---|---|---|
| `auth_expired` | 認証失敗（アプリパスワードの誤り・失効） | アプリパスワードを発行し直して `setup`、`resume` |
| `failed_preserved`（未送信確定） | 通信できない状態が48時間続いた、または Gmail が確定的に拒否した（宛先・上限など） | 原因を直して `python mail_worker.py resume-unsent` |
| `uncertain_preserved` | 送信の途中で接続が切れ、受付の有無が不明 | 自動再送しない。受信箱を確認してユーザーが判断 |
| 通信確認が `False` | 学校ネットワークが 465 番を止めている | スマホのテザリングで試す、学校の情報システム担当に相談する、587番の対応を私に依頼する |
