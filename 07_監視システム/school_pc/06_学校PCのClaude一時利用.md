# 学校PCでの Claude の一時利用（SP-24）

> **位置づけ：** 学校PCで、最初の段階のシミュレーションを進める**基盤を整えるあいだだけ**、Claude を補助として使う（ユーザー判断、2026-11-12）。基盤が整ったら使わない。**無人運転（監視・メール・親ループ）は、Claude なしで動く設計のまま。**

## 1. 範囲（Claude に任せること／任せないこと）
**任せる（基盤の整理）：** [03 セットアップ手順](03_セットアップ手順_段0から8.md) の段0〜8のうち、確認と構築。
- 一括整備 `05_bootstrap.ps1`（まず確認のみ→`-Apply`）、toolchain の検証、AIなしの `config.json` の生成、単体試験の実行。
- メールの設定（`mail_provider`・`mail_sender`・`mail_to`・`mail_enabled_since`）、`smtp_mail.py check`、ワーカーの起動確認。
- 失敗したときの原因の切り分け（コマンド・出力・時刻を記録）。

**任せない（あなたの明示の指示があるまで、しない）：**
- 研究 run の開始・検証・記録（`start-next`・`validate`・`record`）、READY の作成、sv26103006 の再実行、親ループ（`choice_parent_loop.py`）の起動。
- アプリパスワードの入力、`send-test` の `yes`（あなたが入力する）。
- PAP・主要指標・比較方式・除外規則に関わる判断。
- 異常時の自動対応。**異常を検知しても、AI を自動起動しない**（これまでの決定のまま）。

## 2. 導入前に済ませること
1. 学校PCの Windows の初期設定が終わっている（ブラウザ・PowerShell が開く）。
2. 研究フォルダのコピーが終わっている（段1。`02_robocopy.ps1 -Verify` が未コピー 0 件）。
3. Claude の接続とサインインに必要なネットワークに届く（学校のネットワークでの可否は未確認。Gmail の 465 番と同じタイミングで確認する）。

## 3. 導入と設定（ユーザー操作）
1. Claude を、公式の手順で導入し、あなたのアカウントでサインインする（手順は公式の案内に従う）。
2. **権限のモードは既定のまま**（承認を求める設定）。承認を省略する設定にしない。
3. 作業フォルダを、学校PCの研究フォルダ（`<ROOT>`）にする。`<ROOT>\CLAUDE.md` が、研究のルールとして読み込まれる。
4. **学校PCの全体設定** `~\.claude\CLAUDE.md` に、次の最小の内容を書く（開発PCの全体設定は引き継がれないため）：

```text
# 学校PC用の共通指示（一時利用）
- 日本語で、事実と推測を分けて報告する。「ローカル確認済み」「学校PCで確認済み」「未実施」を区別する。
- 秘密情報（パスワード・アプリパスワード・トークン）を、ソース・文書・ログ・チャットに書かない。`~\.jdrt-monitor\` の暗号化ファイル（mail_token.bin、smtp_secret.bin）を読まない。
- `--dangerously-skip-permissions` を使わない。
- 研究 run・READY・start-next・validate・record は、ユーザーの明示の指示があるまで実行しない。
- 最初に `<ROOT>\CLAUDE.md` と `<ROOT>\context.md`（AGENT_CURRENT_END まで）を読む。
- 破壊的操作・外部送信は、ユーザーの承認を得てから行う。
```

## 4. 作業中の約束
- **書き込み役は1台だけ。** 学校PCで動かす前に、開発PC側の監視と実行を止める。開発PCと学校PCで、別々のコピーに対して、同じセルを動かさない。
- 作業の内容と結果は、`05_タスク管理/jdrt/独立監視システム_導入タスク.md` に記録する（コマンド・出力・時刻・SHA）。
- 使用量は、同じアカウントの開発PCと共有される。2台で並行して長く使わない。

## 6. 後片付け（使い終えたら）
1. **無人運転が Claude に依存していないことの確認：** 監視タスク・ワーカー・親ループは、Claude のプロセス・スキル・フックを使わない。`diagnostics_enabled` が `false`、`codex`・`claude` のプロセスが監視から起動されていない。
2. Claude の**サインアウト**と、アンインストール。アカウント側で、この端末のセッションを、取り消せるか確認する（公式の案内に従う）。
3. `~\.claude\` の、設定・会話の記録（`projects\`）・サインイン情報を、残すか消すかを決める。**会話の記録には、実行したコマンドと出力が残る。** 秘密は貼っていないが、パスや構成の情報は含まれる。
4. 作業用の一時ファイル（試験用の設定 `~\.jdrt-monitor\mailtest\` など、不要なもの）を整理する。**監視の `runtime` と `config.json`、`outbox`、暗号化されたトークンは消さない。**
5. 研究フォルダの未コミットの変更がないか確認する（学校PCは、開発メモを読むだけ。編集はメインPCのみ）。
