# 学校PCの運用条件：電源・画面ロック・サインアウト・再起動・Wi-Fi（SP-08）

作成 2026-11-07。**書いてあるのは `install.ps1`・`watch.py`・README の記述から読み取れる設計上の振る舞いであり、学校PCでの実測ではない。** 「実機で確認」と書いた欄は段8で1つずつ観察して、結果を追記すること。**自動復旧を主張しない。** 監視は「検知して保全・通知」まで、研究 run の再開はユーザーの指示後。

## 根拠：`install.ps1` の実記述

| 設定 | 記述（`install.ps1`） | 意味 |
|---|---|---|
| 実行体 | `pythonw.exe -B -X utf8 "<watch.py>" run`、作業ディレクトリ＝`07_監視システム` | 画面なしの常駐。研究 run を起動・停止する処理は含まない |
| 主体 | `New-ScheduledTaskPrincipal -UserId <登録ユーザー> -LogonType Interactive -RunLevel Limited` | **そのユーザーが Windows にサインインしている間だけ**、そのセッションで動く。サインアウト中は動かない。昇格なし |
| 起動トリガ1 | `New-ScheduledTaskTrigger -AtLogOn -User <登録ユーザー>` | サインイン時に起動 |
| 起動トリガ2（救済） | `-Once -At (Get-Date).AddSeconds(5) -RepetitionInterval 1分` | 毎分、起動を試みる。`RepetitionDuration` は未指定のため、**無期限に繰り返されるかは実機で `Get-ScheduledTask JDRT-SimulationWatch \| % Triggers` の Repetition で確認** |
| 多重起動 | `-MultipleInstances IgnoreNew` ＋ `watch.py` 内の OS lock（`runtime\monitor.lock`） | 稼働中なら毎分トリガは無視される。二重 writer を防ぐ |
| その他 | `-StartWhenAvailable`、`-ExecutionTimeLimit 0`、`-AllowStartIfOnBatteries`、`-DontStopIfGoingOnBatteries` | 開始時刻を逃したら可能になり次第起動／実行時間の打切りなし／バッテリーでも開始・継続 |
| **無いもの** | `-WakeToRun`、`-RunOnlyIfNetworkAvailable`、`-RestartOnFailure`、`-RunLevel Highest`、サインアウト後も動く設定（`S4U`／パスワード保存） | スリープから起こす・ネット待ち・失敗時再起動・非サインイン実行は**設計に含まれない** |
| 研究 run との関係 | 監視は読取中心。run の開始・検証・記録・kill はしない（README） | **シミュレーション本体は監視とは別の経路で起動される。** 現時点で学校PC用の無人起動（SP-06）は未実装。ユーザーが手動で起動した場合は、起動したセッションのサインアウトで止まり得る（Windows 一般の挙動。実機で確認） |

## 状態別の振る舞いと対応範囲

凡例：「対応する」＝監視が検知・保全できる。「対応しない」＝自動復旧は行わない。

| 状態 | 監視タスク | シミュレーション（別プロセス） | 対応範囲 | **対応しない範囲（自動復旧を主張しない）** | 実機で確認 |
|---|---|---|---|---|---|
| **画面ロック**（Win+L、画面オフ） | 継続（サインインは維持され、Interactive セッションは生きる） | 継続 | ロック中も監視・イベント保存は続く。Windows 通知（トースト）はロック中は見えないことがある（受信箱 `status.html`・将来のメールで確認） | ロック解除の自動化はしない | ロック30分後も `watch.py status` の観測時刻が更新される。run 側のログが伸びる |
| **スリープ／モダンスタンバイ** | 全停止（プロセスは保持されるが CPU 停止）。`-WakeToRun` が無いのでタスクは PC を起こさない | 停止（シミュレーション時刻も止まる） | 復帰後、保持されたプロセスは続きから動く可能性がある。監視は復帰後に観測を再開。実所要時間にスリープ分が含まれる（README の実時間定義） | **スリープ中は検知も通知もできない。** 復帰直後、「シミュレーション時刻10分不変」の停滞誤検知や PID 不明の異常イベントが出る可能性がある（未検証）。ネットワークが切れたまま復帰することもある | 短いスリープ（1〜2分）で人工プロセスを使い、復帰後のイベント有無を観察 |
| **休止（ハイバネート）** | 同上（復帰後にプロセスは復元される想定） | 同上 | スリープと同様 | 復帰失敗時は何も残らない。**休止の無効化を推奨** | 同上（可能なら） |
| **サインアウト（ログオフ）** | 停止（`Interactive` はそのユーザーのセッション内でしか動かない） | そのセッションで起動した研究プロセスは終了し得る | 再サインイン時（`AtLogOn`）に監視が再起動し、孤立した RUNNING を**検知して通知・保全**する設計 | **サインアウト中は監視もメールも動かない。** run は自動再開しない。サインアウト後も計算を続ける構成（`S4U`／パスワード保存）は採用していない。RDP を抜くときは「サインアウト」でなく「切断」を使う | サインアウト→再サインインで、監視が1分以内に復帰し、RUNNING の扱いを status で確認 |
| **OS 再起動**（更新・電源断含む） | 停止 → **ユーザーがサインインした後**に `AtLogOn` で起動。自動サインインは設定しない（下記） | 停止（PID・途中状態は引き継げない） | サインイン後、監視が立ち上がり、孤立した RUNNING（PID 消失）を**異常として保全・通知**する設計。後続セルの自動開始は抑止の方針 | **再起動後の自動復旧はしない。** 無人の学校PCが再起動すると、誰かがサインインするまで何も動かない。Windows Update の自動再起動に注意 | 再起動→サインインして、監視が起動、旧 run の異常が1回だけ通知され、過去履歴の再通知が無いこと |
| **Wi-Fi 切断** | 継続（監視はローカルのみ。`RunOnlyIfNetworkAvailable` なし） | 継続（入出力はローカルディスク。研究フォルダをネットワーク共有に置かない前提） | 通知イベントは**ローカルディスクに保存**され、メール送信は通信失敗として再試行対象（`mail_outbox` の「未送信は再試行、受付不明は再送しない」）。復帰後に未送信分を送る設計 | **切断中はメールが届かない。** 異常を外へ知らせられない。送信ワーカーは未実装（SP-04 文書）なので、現状は投入までで、無人送信は成立しない。学校PC自体の電源断・ネット断を外から知らせる死活監視は含まない。Wi-Fi 省電力でアダプタが落ちる場合がある | Wi-Fi を数分切って再接続。イベントが保存され、重複しないこと |
| **監視プロセスだけが落ちた** | 毎分トリガで再起動（`IgnoreNew` で稼働中は無視） | 影響なし（監視は読取専用） | 最長約1分で復帰し、`state.json` から再開。過去イベントは再通知しない | 落ちていた約1分の検知遅れ。原因不明なら `runtime\monitor_failures.jsonl` に例外種別が残る | `Stop-ScheduledTask` の後の復帰時間 |

## 推奨設定（ユーザーが学校PCで設定するもの。私は変更しない）

学校PCが大学管理で、ポリシーが以下を上書き・禁止している可能性がある。変更できない項目は**その制約を記録し、運用（サインインしたまま・電源接続）で守る**。

| 項目 | 推奨 | 設定例（管理者権限が要る場合あり） |
|---|---|---|
| スリープ（電源接続時） | 「なし」 | 設定 > システム > 電源 > 画面とスリープ。または `powercfg /change standby-timeout-ac 0` |
| 休止 | 無効（または「なし」） | `powercfg /change hibernate-timeout-ac 0`、必要なら `powercfg /hibernate off` |
| 画面オフ | 任意（画面オフは計算に影響しない。15〜30分で可） | `powercfg /change monitor-timeout-ac 15` |
| ノートPCの蓋 | 電源接続時「何もしない」。蓋を閉じるとスリープする機種がある | `powercfg /setacvalueindex SCHEME_CURRENT SUB_BUTTONS LIDACTION 0` の後 `powercfg /setactive SCHEME_CURRENT` |
| 電源 | **AC 接続を維持**。バッテリー運用にしない | – |
| 画面ロック | 有効のままでよい（自動ロックを残す）。サインアウトはしない | スクリーンセーバーの「再開時にログオン画面に戻る」は可 |
| Windows Update | 勤務時間外の自動再起動を避ける（アクティブ時間、再起動の通知）。大学管理ならポリシー優先。更新で再起動したら、誰かが再サインインして再起動時の確認と同じ手順で状態を確認する | 設定 > Windows Update > 詳細オプション > アクティブ時間 |
| Wi-Fi 省電力 | アダプタの「電力の節約のためにデバイスの電源をオフにできる」を外す | デバイスマネージャー > ネットワークアダプター > 電源の管理 |
| 自動サインイン | **既定では設定しない**（共有・大学PCでパスワードを保存することになる）。再起動後も自動で走らせたい場合は、ユーザー判断と `S4U` タスクへの設計変更が別途必要（今回の範囲外） | – |
| リモート操作 | RDP等は「切断」で抜ける。「サインアウト」しない | – |

## 結論として主張しないこと

- 「無人で、サインアウト・再起動・スリープをまたいで研究が続く」とは主張しない。
- 「異常が起きたら自動で直る」とは主張しない（自動 kill・自動再実行・自動AI呼出しは仕様として行わない）。
- 学校PC自体が止まった場合の外部への通知は、この構成では保証されない。
