## Q1 `--prior-readback`：経路A（推奨）

- 既存の readback で最新は sv26103005 のもの（`sq26103005_manual_finish/…`）。開発PCで、これを渡した `preflight` は `PRIOR_READBACK_INVALID`（6セルの証明にならない）。
- **経路A：7番目を、既存の手順で手動実行し、7セル分の readback を作る。** 前例（sv26103005）があり、試験済みの部品だけで済む。最初のセルを人が見られる。経路B（直接CLIの記録を読み戻せるようツールを拡張）はコード変更とレビューが要る。経路C（readback を手で作る）は証跡の捏造なので不可。
- **手順の順序（レビューで追加）：** `start-next` → `check` → `choice_finish_cell.py`（validate と record を含む）→ `choice_record_readback.py --output …` → その後に表示同期（`choice_sync_status --apply`）。
  - **readback が終わるまで、記録7ファイルを誰も編集しない。** readback は、7ファイルのSHAが finish 時と一致することを要求する。同期は、そのうち3ファイル（context.md・現状把握の md/html）を書き換えるので、必ず readback の後。
  - `--output` は必須。出力先は goal フォルダの中、親ディレクトリが既にあり、既存ファイルは不可。`--prior-readback` はプロジェクトの内側に置く。
  - コマンドの引数は、`SKILL.md` と各 `--help` で確認してから実行する（このシートの記述は、コードの読取に基づく案）。

1. **結果の戻し方：** 学校PCからは push できない。run の出力は1本あたり数百MB。全体の戻し方（USB か）と時期。
2. **書き込むのは1台だけ：** record は追跡対象の7ファイル（context.md・決定ログ・現状把握 md/html・台帳など）を学校PCで書き換える。これは「学校PCでは管理下を編集しない」と `git pull --ff-only` に反し、開発PC側の更新（未コミット分を含む）と衝突する。**系列が続く間は、開発PCでこの7ファイルを編集しない・record をしない、学校PCで pull しない**取り決めが要る。その後の `git checkout origin -- <path>` は、学校PCの7行目やマーカーを消す（partial_records または台帳行の喪失）ので、してはいけない。

## 曖昧な点（何が／選択肢／判断と理由）

1. 6セル目の readback がない：A（7番目を手動で実行して7セル分を作る）／B（読み戻しツールの拡張）／C（手作り）→ **A**。前例があり、試験済みの部品だけで済む。Cは捏造。
2. SP-09 と D5 の指示2の比較対象：完了扱い／形を変えて維持 → **完了扱い**。環境試験は smoke 06・07 の比較で代える。
3. 出力SHAの比較方法：生／展開した中身 → **展開した中身**（生は毎回違う）。
4. 文書の現在値の食い違い：context.md／台帳 → **台帳とCLIの status**。context.md の修正は、どの機械が書くかを決めた後に行う。
5. 別の環境（4つ目）の run を混ぜてよいか：新しい READY で吸収／再登録 → D5 の①②（差がパス3項目だけ）を満たす限り、**吸収**。満たさなければ U3。
