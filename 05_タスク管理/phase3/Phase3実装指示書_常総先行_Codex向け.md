## A-2. 救出走行の実装＋シナリオA注入・full再実行
**[Claude Code：新規実装]** 救出走行 trip 生成
- 各非保有世帯メッシュに対し**2レグtrip**：`車保有メッシュ（最寄り/同一）発 → 非保有世帯メッシュで乗車（停車時間 e.g. 60s）→ 指定避難所着`。
- 台数 = 浸水域内**非保有世帯数 × r**（r=1.0）。**非保有世帯数（メッシュ別）= total_pop × 非保有率0.15 ÷ 2.3**（`HOUSEHOLD_SIZE`）。
- 出力：`scenario_a.rou.xml`（full）に救出走行車両を追記（id接頭辞 `rescue_`）。自家用車（車保有世帯分＝total_pop×0.85÷2.3 の ceil）とは別カウント。
- パラメータは config 化（r, 非保有率, k）し感度で振れるようにする。

**[Codex：実行・再固定]**
```
python scripts/p2_region_pipeline.py scenario-city --city-code 08211 --scenario full
python scripts/p2_region_pipeline.py run-city --city-code 08211 --scenario full
```
- **検証**：`scenario_a.rou.xml` の車両内訳が P3-IMPL-0 会計と整合（自家用車≈8,164台＋救出走行≈1,405台＝合計≈9,569台）。TraCI summary が生成される。

## A-3. シナリオB（デマンドバス）の実装
**[Claude Code：新規実装]**
- バス5台（標準8人×4＋福祉4人×1）。固定ルート（住宅密集メッシュ→指定避難所、上限9往復/6h）。`busStop` 設置。Type3/4エージェントの乗降。SUMO の公共交通（`.rou.xml` の `<vehicle>`+`<stop>`）または TraCI で運行制御。
- **救出走行の削減（会計連動）**：シナリオBの救出走行台数 = 非保有世帯数×r −（**バス実輸送人数** ÷ k=2.3）。バス実輸送人数は TraCI で集計。**バス定員超で乗れないType3/4はシナリオAと同一（救出走行を残す）**＝会計クローズ。
- 出力：`scenario_b.rou.xml`、バス運行ログ（各バスの往復数・乗車人数・所要時間 CSV）。

**[Codex：実行]** シナリオB（full）を生成・実行し、A/B両方の full 結果を揃える。

## A-4. 指標算出・床効果の再評価
**[Claude Code：新規/拡張]** `p2_evaluate_results.py` を人単位・Type別に拡張
- **逃げ遅れ（人単位）**＝終了時点で避難所未到着の人数（世帯車1台=2.3人／救出走行1台=k人／バス=実乗車。用語定義集準拠）。
- **避難完了時間の分布**（全体・Type別）、**渋滞指標**（区間平均速度・最大停止台数・総旅行時間）、**公平性指標**（Type3/4の避難完了率・平均完了時間）。
- **床効果の判定**：約2万人規模で渋滞由来の逃げ遅れが発生するか。発生すれば逃げ遅れを主指標に、発生しなければ避難完了時間分布・safety margin を主指標に昇格（T-D-C2）。

**[Codex：実行]** 集計スクリプト実行、A/B比較CSV（人単位・Type別）と図を生成。
