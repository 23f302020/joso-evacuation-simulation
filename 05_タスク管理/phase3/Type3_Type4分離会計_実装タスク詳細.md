# Type3・Type4分離会計 実装タスク詳細

> 作成日：2026/07/21  
> 状態：**実装・集計完了。共通seed 4組を確定し、5組目のA側runは実行時間制約により未完**  
> 目的：高齢者かつ自家用車を利用できないType4について、Type3と分けた避難完了率・未到着人数を、重複のない個人単位で比較できるようにする。

## 1. 現状と必要性

現行の正式評価はType3とType4を合算し、固定分母3,231.5人に対する完了率を計算している。入力表にはType3 2,320人、Type4 935人が存在し、バスログには利用者の種別がある。一方、救出走行は1台2.3人相当の集約会計であり、どの個人が救出車両またはバスへ割り当てられたかを追跡できない。既存ログだけからType4の厳密な完了・未到着を復元すると、重複や端数配分が生じる可能性がある。

このため、既存正式結果を後処理で書き換えず、個人台帳と交通手段の排他的割当を導入した別実験として計画する。

### 2.1 2026/07/21の採用内容

ユーザーの実装指示を受け、J1〜J5・J7は推奨案を採用した。J6は同一seed 4組まで成立し、seed 101のA側は強い渋滞による実行時間制約で未完となった。J8は現行B側と同じ救出走行置換型だけを対象とし、純追加型は別実験として実装しなかった。既存正本8runは変更せず、分離会計を追加診断として管理する。

## 6. 必須の不変条件

1. 各runのType3分母は2,320人、Type4分母は935人で固定する。
2. 各個人は同一run内で1つの交通手段にだけ割り当てる。
3. `arrived + waiting + onboard + vehicle_unarrived + unassigned = denominator` を種別ごとに満たす。
4. バス到着者は乗車済みかつバスが避難所へ到着した個人だけとする。
5. A/Bの個人集合と属性は同じで、変えるのは政策条件だけとする。
6. 100%を超える完了率、負の人数、未知ID、重複IDが1件でもあればrunを正式集計へ入れない。
7. 現行の8runと新実験runを同じ集計表へ混ぜない。

## 7. 検証計画

### 単体検証

- 同じseedから同じ`person_id`と割当が生成される。
- Type3/4人数が入力表と一致する。
- バス割当者が救出割当へ残らない。
- 車両またはバスの到着が、その車両へ属する個人に一度だけ伝播する。
- 未到着車両の乗員を到着へ数えない。

### small試行

各種別から数人を手作業で追跡し、入力人口→台帳→手段割当→SUMO ID→終了状態→集計値が一致することを確認する。不一致時はfullへ進まない。

### full試行

同一seedのA/Bペアを最低5組実行する。主指標はType4避難完了率とType4未到着人数、副指標はType3同指標、手段別到着人数、時刻別累積完了率とする。中央値、範囲、ペア差を示し、単一runだけで結論を出さない。

## 8. 実施順と停止条件

```text
判断固定 → 台帳スキーマ → 台帳生成 → A割当 → B排他割当
→ 個人別ログ → 評価器 → 単体テスト → small → full → 図表・文書
```

次の場合は実装または実行を停止する。

- T34-J1〜J8のいずれかが未決定。
- 入力のType3/4整数人数と正式分母の扱いが合意されていない。
- A/Bで同一個人集合を生成できない。
- バスと救出走行の重複割当が1件でもある。
- small試行で個人単位の人数保存が成立しない。
- 現行正本を上書きする可能性がある。
