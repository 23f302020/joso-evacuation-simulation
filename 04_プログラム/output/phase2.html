Phase 2：SUMO動的交通流

実装済み

Phase 2では、Phase 1の閉鎖道路と避難需要をSUMOネットワークへ接続し、車両相互作用、動的閉鎖、再経路探索を実装します。ここで示す旧small・10pct・fullは交通流基盤の結果であり、Phase 3の正式Scenario A（自家用車＋救出走行）とは区別します。

確認できる内容

  • 常総市のsmall / 1/10 / 全量試行における到着・未到着・逃げ遅れ候補
  • 60秒間隔のアクティブ車両数、平均速度、停止台数による混雑推移
  • 国道294号、国道・県道354号、県道357号、常総IC接続部の主要避難路別混雑
  • 41市区町村へ拡張したPhase 2 SUMO入力・結果一覧

Phase 2の到着・未到着はSUMO既定teleport設定下の記録値であり、「渋滞由来の逃げ遅れは発生しない」という一般主張はしません。

試行規模別の交通状態

旧単一run・SUMO既定teleport=300秒の結果です。実装基盤と時間変化の説明に限定し、一般的な逃げ遅れ確定値やPhase 3の正式A/B判定には使用しません。

SUMOの使い方と入力データの取得方法

SUMOは道路上の車両移動を再現する交通シミュレーターです。本研究では、地図・人口・避難所・浸水データをSUMO用ファイルへ変換し、Pythonから道路閉鎖を時間ごとに反映しました。

1 / 道路

走行できる道路を作る

OpenStreetMap由来の道路をnetconvertで.net.xmlへ変換し、交差点と道路のつながりをSUMOへ読み込みます。

2 / 避難需要

車の出発地と台数を作る

250m人口メッシュから出発地点と車両数を作り、最寄りのSUMO道路へ結び付けます。

3 / 目的地

安全な避難所を設定する

洪水対応避難施設から浸水想定区域内の施設を除き、目的地をSUMO道路へ結び付けます。

4 / 浸水

道路を時間ごとに閉鎖する

浸水深0.5m以上と判定した道路を、PythonのTraCIから閉鎖し、走行中の車へ別経路を探させます。

本研究での実行手順

  1. SUMOを導入する：SUMO公式の導入手順から本体を入れ、sumo --versionとnetconvert --versionで確認する。本研究の確認済み版は1.26.0。
  2. 道路網を作る：道路データをjoso.osm.xmlへ変換し、netconvertでjoso.net.xmlを生成する。OpenStreetMapの読み込み方法はSUMO公式資料を参照する。
  3. 出発地・避難所・閉鎖道路を接続する：人口メッシュと避難所を最寄りのSUMO道路へ対応付け、Phase 1の道路IDをSUMOの道路IDへ変換する。
  4. 車両と設定を作る：.rou.xmlへ車両の出発地・目的地、.sumocfgへ道路網・車両・実行時間を記録する。
  5. 実行して確認する：SUMOまたはSUMO-GUIを起動し、TraCIから道路閉鎖と再経路探索を行う。到着・未到着、速度、停止台数をCSVへ保存する。

cd 04_プログラム
python scripts/download_data.py

data/manifest.csvでdirect_zipのデータは自動取得・展開されます。manualのデータは表示された公式URLから取得し、指定された保存先へ配置します。大容量の生データはGitへ登録せず、利用規約と取得時点を確認してください。
