2015 鬼怒川氾濫 / 茨城県常総市

常総市の洪水避難研究

現在：常総市JDRT v2中核7/20

GitHub

この研究について

2015年の鬼怒川氾濫を事例に、常総市で道路が通れなくなる状況を再現し、限られた避難車両を誰のところへ先に向かわせると避難を助けられるかを調べる卒業研究です。今後の実装と実験は常総市だけに絞ります。

🌊

研究の背景

2015年9月、鬼怒川の氾濫で常総市が浸水。自家用車避難が集中し道路が混雑したほか、車を持たない高齢者など要支援者の避難が困難でした。この課題を数値的に評価します。

🗺️

Phase 1：経路検索

浸水により閉鎖される道路を除き、避難所へ到達できる経路があるかを確認する静的な分析です。茨城県内41市区町村を対象にしています。

🚗

Phase 2：交通流シミュレーション

SUMOという交通シミュレーターで車両相互作用、道路閉鎖、再経路探索を実装しました。旧結果は単一run・テレポート300秒のため、交通流基盤として扱います。

🚌

現在：常総市JDRT

避難を待つ時間、支援の必要度、道路が通れなくなる見込みを使い、車両の迎え先を運行中に決め直す仕組みです。v1は技術停止して保全し、共通条件を改訂したv2の中核20セルを進めています。

今後の中心：常総市JDRT

この研究でできること：洪水で道路が順番に通れなくなる状況の中で、避難車両が「近い人から迎える場合」と「待ち時間・支援の必要度・道路閉鎖の見込みを考えて迎える場合」を同じ条件で比べられます。どの方法が常に良いかを先に決めず、助かった人数、待ち時間、取り残された理由、車両の無駄な移動を確認します。

  • 対象は常総市だけ。ほかの市町村の大容量結果は削除せずアーカイブへ移動済み
  • 配車の基礎部品、会計検査、SUMO連携、小規模確認は完了
  • v2はseed 23423の4方式と、seed 42のB3・B2・P1が技術ゲートを通過（中核7/20）
  • 次はP2-L15 seed 42。20セル完了前に方式の良し悪しは判断しない

これまでのPhase 3確定結論

正式結論：本研究で実施した条件と試行回数の範囲では、デマンド交通車両を固定経路避難シャトルとして導入した場合と、バスを導入せず自家用車と救出走行で避難した場合の間で、Type3/4避難完了率の一貫した改善または悪化は確認できませんでした。本モデルの分解能では、方向性のある差を検出できませんでした。

  • Scenario A：自家用車8,164台＋救出走行1,405台、A側3run
  • Scenario B：自家用車8,164台＋救出走行1,351台＋固定経路避難シャトル、B側5run
  • バスは各runで75〜165人を避難所へ輸送。ただし地域全体の完了率改善とは分けて解釈

「バスに効果がない」「両条件が同等」という証明ではありません。15組は8runを組み替えた非独立な比較です。
