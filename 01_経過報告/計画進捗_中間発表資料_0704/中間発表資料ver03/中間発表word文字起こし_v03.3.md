河川氾濫時における自家用車避難とデマンド交通バス活用の比較シミュレーションに関する研究

眞坂研究室　氏名：古賀玲次

## 1. はじめに

地域公共交通として導入されているデマンド交通は，平時の移動支援手段として期待される一方で，利用者数や運行費用の面から継続性が課題となる場合がある[5]．本研究では，デマンド交通に平時以外の付加価値を持たせる一案として，河川氾濫時の避難支援への活用可能性に着目する．

対象事例は，平成27年9月関東・東北豪雨に伴う鬼怒川氾濫である．2015年9月10日，茨城県常総市三坂町付近で鬼怒川左岸の堤防が決壊し，市域の広い範囲で浸水被害が発生した[1][2]．水害時の自動車避難では，車両が動けなくなる危険や避難経路上の混雑が指摘されている[6][7]．

避難支援には，徒歩避難，家族・近隣住民による送迎，福祉輸送，自治体バスなど複数の方法がある．本研究では，これらの避難支援手段のうち，既存のデマンド交通バスを災害時避難に活用する案を検討対象とする．今回の発表では，研究の背景，使用予定データ，シミュレーション構築方針，今後の作業計画を報告する．

## 2. 研究全体の流れと使用データ

本研究では，浸水データ，道路ネットワーク，人口メッシュ，避難施設データを組み合わせ，河川氾濫時の避難をシミュレーションする．全体の流れは，浸水範囲から通行困難道路を設定し，避難所までの経路を確認したうえで，自家用車のみの場合とデマンド交通バスを活用する場合を比較するものである．

表1．研究フェーズの位置づけ

| フェーズ | 目的 | 主な入力 | 作成予定の内容 |
|---|---|---|---|
| Phase 1 | 浸水時に利用できない道路を設定し，避難所までの経路を確認する | 浸水範囲，道路ネットワーク，出発地，避難所 | 閉鎖道路リスト，避難経路確認用データ |
| Phase 2 | 自家用車のみで避難する場合の交通流を設定する | Phase 1の閉鎖道路，SUMO道路ネットワーク，車両ルート | 自家用車避難シナリオ，交通流シミュレーション条件 |
| Phase 3 | デマンド交通バスを導入する場合の避難支援効果を比較する | Phase 2の基準シナリオ，バス需要候補，バス運行条件 | バス活用シナリオ，比較用評価指標 |

本研究で使用する主なデータとツールを表2に示す．各データに何が含まれており，研究でどのように活用するのかを整理する．

表2．主なデータ・ツールと本研究での役割

| 略称・用語 | 内容 | 本研究での使い方 |
|---|---|---|
| GSI KML | 国土地理院が公開した浸水範囲の時系列データである．KMLは地図上に線や面を表示するための地理情報ファイル形式である | 浸水範囲が時間とともにどの方向へ広がるかを把握する |
| A31a | 国土数値情報の洪水浸水想定区域データである．想定される浸水範囲を面データとして持ち，浸水深を段階的に示す浸水深コードを含む | 浸水深0.5m以上に相当する範囲を抽出し，道路閉鎖候補を作る |
| N03 | 国土数値情報の行政区域データである．市町村界を含む | 常総市および茨城県内対象市区町村の範囲を切り出す |
| P20 | 国土数値情報の避難施設データである．施設位置や対応する災害種別を含む | 洪水に対応する避難所を抽出し，目的地候補として用いる |
| 250m人口メッシュ | 250m四方ごとの人口集計データである | 浸水範囲内または周辺の居住者を出発地として設定する |
| GraphML | 道路を交差点などのノードと道路区間であるedgeとして保存する形式である | 避難経路検索とSUMOネットワーク変換の元データに使う |
| SUMO | Simulation of Urban MObilityの略で，道路ネットワーク上で車両を走行させる交通流シミュレータである | 自家用車やバスを道路上で走行させるシミュレーションに使う |
| TraCI | PythonからSUMO実行中の車両や道路状態を操作する仕組みである | 時刻に応じた道路閉鎖や，閉鎖後の経路再探索を設定する |
| SUMO edge | SUMO内の道路区間を表すIDである | Phase 1で抽出した閉鎖道路をSUMO上の道路区間へ対応付ける |
| `joso.net.xml` | 常総市道路ネットワークをSUMO用に変換したファイルである | SUMO上で車両が走る道路として使う |
| `closure_timeline_sumo.json` | 時刻別に閉鎖する道路をSUMO edge IDで表したファイルである | TraCIで道路閉鎖を行う入力として使う |

道路閉鎖は，SUMOが自動的に計算するものではなく，浸水データから事前に設定する条件である．具体的には，A31aの浸水想定区域から浸水深0.5m以上に相当する範囲を抽出し，その範囲と道路リンクが重なる場合に，その道路を通行困難道路として扱う．これは，浸水深0.5m程度で自動車走行が危険になることが示されているためである[7][8]．

浸水時系列t0〜t7は，浸水範囲が広がる段階を表す時点である．本研究では，これらの時点をSUMO上の0〜21,600秒に対応付け，時間の経過に応じて道路閉鎖が増える条件を作成する予定である．道路が閉鎖された場合，SUMO上の車両は通行できる別経路を探索する設定とする．

## 3. 研究計画

本研究では，まずPhase 1として，浸水時に通行困難となる道路を抽出し，避難所までの経路確認を行う．出発地は，浸水範囲内またはその周辺に含まれる250m人口メッシュを用いて設定する．このメッシュは，居住者の分布を道路ネットワーク上の出発地点へ対応付けるために用いる単位である．

避難所は，P20避難施設データのうち洪水に対応する施設を候補とする．洪水対応避難所とは，避難施設データ上で洪水災害への対応が示されている施設である．ただし，避難所自体が浸水想定区域内にある場合も考えられるため，浸水範囲との位置関係を確認し，目的地として利用する条件を整理する．

Phase 2では，Phase 1で作成した閉鎖道路をSUMO edge IDへ変換し，SUMO上で時刻別に道路を閉鎖できるようにする．そのうえで，自家用車のみで避難する基準シナリオを作成する．車両数は，常総市全体の人口や自動車保有台数をそのまま用いるのではなく，対象とする人口メッシュに含まれる人口から設定する．これにより，浸水の影響を受ける可能性がある地域を対象に避難車両を配置する．

Phase 3では，既存のデマンド交通バスを避難支援に用いるシナリオを作成する．この段階では，自家用車のみの場合を基準として，バスを導入した場合に避難できる人数，未到着となる車両や住民，主要道路の混雑がどのように変化するかを比較する．デマンド交通以外の徒歩避難，家族・近隣住民による送迎，福祉輸送，自治体バスなどは，本研究では比較対象の候補として整理し，必要に応じて今後の課題に位置付ける．

## 4. 今後の作業予定

今後は，まず使用データの前処理を行う．具体的には，GSI KMLとA31aを用いた浸水範囲の整理，N03を用いた対象地域の切り出し，P20を用いた洪水対応避難所の抽出，250m人口メッシュを用いた出発地の設定を行う．

次に，道路ネットワークと浸水範囲を重ね合わせ，通行困難道路を抽出する．その後，Phase 1では閉鎖道路を除いた道路ネットワーク上で避難所までの経路確認を行う．Phase 2では，閉鎖道路をSUMO edge IDへ対応付け，SUMOとTraCIを用いた自家用車避難シナリオを作成する．

最後に，Phase 3としてデマンド交通バスを導入する条件を設定する．バスの乗車対象者，乗降地点，避難所，運行台数，経路選択方法を整理し，自家用車のみの場合と比較できる評価指標を作成する予定である．評価指標としては，到着人数，未到着人数，主要避難路の混雑，バス輸送人数などを検討する．

## 5. おわりに

本研究では，2015年鬼怒川氾濫を事例に，浸水時の道路閉鎖を考慮した避難シミュレーションの構築を計画している．今後は，浸水データ，道路ネットワーク，人口メッシュ，避難施設データを組み合わせ，自家用車避難の基準シナリオとデマンド交通バス活用シナリオを作成する．これにより，河川氾濫時におけるデマンド交通バスの避難支援手段としての活用可能性を検討する．
