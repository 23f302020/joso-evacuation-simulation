## 3. 追加・修正した説明項目

### 3.1 研究全体の流れ

ver03.1では，本文2章で次の順序を明示した。

1. 浸水データと道路ネットワークを重ねる。
2. 浸水深0.5m以上に相当する範囲と重なる道路を通行困難道路として扱う。
3. Phase 1で，通行困難道路を除外した場合に避難所までの経路が残るかを確認する。
4. Phase 2で，同じ閉鎖条件をSUMOに渡し，自家用車を走行させて到着・未到着・混雑を確認する。
5. Phase 3で，デマンド交通バス導入時の結果とPhase 2を比較する。

### 3.2 略称説明

本文では，初出時に次の説明を追加した。

| 略称・用語 | 説明 |
|---|---|
| GSI KML | 国土地理院が公開した浸水範囲の時系列データ。KMLは地理情報を表すファイル形式 |
| A31a | 国土数値情報の洪水浸水想定区域データ。浸水深コードを持つ面データ |
| N03 | 国土数値情報の行政区域データ。市町村境界の抽出に使用 |
| P20 | 国土数値情報の避難施設データ。洪水対応避難所の抽出に使用 |
| GraphML | 道路ネットワークをノードとエッジで保存する形式 |
| SUMO | 道路ネットワーク上で車両を走行させる交通流シミュレータ |
| TraCI | PythonからSUMO実行中の道路閉鎖や再経路探索を操作するための仕組み |
| edge | 道路ネットワーク上の道路リンク。SUMOでも道路区間をedgeとして扱う |
| net.xml | SUMOで使用する道路ネットワークファイル |
| closure_timeline_sumo.json | SUMO edge IDに変換した時刻別道路閉鎖リスト |

### 3.3 結果説明の補強

結果の数値を出す前に，何を数えた値かを説明するように修正した。

| 結果 | ver03.1での説明 |
|---|---|
| Phase 1 到達不可17メッシュ | 閉鎖道路を除いた道路グラフ上で，洪水対応避難所までの経路が存在しなかったメッシュ数 |
| Phase 1 人口952人，高齢者223人 | 到達不可17メッシュに含まれる人口と高齢者数 |
| Phase 2 full 1,001台 | 常総市全車両数ではなく，対象40メッシュの人口を世帯換算して設定した避難車両数 |
| Phase 2 到着987台 | SUMO上で出発し，安全避難所へ到着した車両数 |
| Phase 2 未到着14台 | 渋滞で到着できなかった車両ではなく，閉鎖済み出発edgeから発車できなかった車両 |
| 主要道路の混雑 | 車両が集中した路線を確認するため，国道294号や県道357号の最大車両数・停止車両数を集計したもの |

## 4. ver03.1作成時の反映ルール

- 略称は初出で説明する。
- ファイル名だけを本文に出さず，必ず「何を表すデータか」を添える。
- Phase 1は静的な経路存在性，Phase 2は動的な車両流として書き分ける。
- Phase 1の到達不可人口とPhase 2の未到着車両数は，単位が異なるため直接比較しない。
- Phase 2の14台は，混雑による未到着ではなく，閉鎖済み出発edgeから発車できなかった車両として説明する。
- 41市区町村の10pct試行は，常総市詳細試行とは別に，広域展開時の確認結果として扱う。
