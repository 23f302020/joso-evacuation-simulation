河川氾濫時における自家用車避難とデマンド交通バス活用の比較シミュレーションに関する研究

眞坂研究室　氏名：古賀玲次

## 1. はじめに

地域公共交通として導入されているデマンド交通は，平時の移動支援手段として期待される一方で，利用者数や運行費用の面から継続性が課題となる場合がある[5]．本研究では，デマンド交通に平時以外の付加価値を持たせる一案として，河川氾濫時の避難支援への活用可能性に着目する．

対象事例は，平成27年9月関東・東北豪雨に伴う鬼怒川氾濫である．2015年9月10日，茨城県常総市三坂町付近で鬼怒川左岸の堤防が決壊し，市域の広い範囲で浸水被害が発生した[1][2]．水害時の自動車避難では，車両が動けなくなる危険や避難経路上の混雑が指摘されている[6][7]．

避難支援には，徒歩避難，家族・近隣住民による送迎，福祉輸送，自治体バスなど複数の方法がある[9]．本研究では，これらの避難支援手段のうち，既存のデマンド交通バスを災害時避難に活用する案を検討対象とする．今回の発表では，研究の背景，使用予定データ，シミュレーション構築方針，今後の作業計画を報告する．

## 2. 研究全体の流れと使用データ

本研究では，浸水データ，道路ネットワーク，人口メッシュ，避難施設データを組み合わせ，河川氾濫時の避難をシミュレーションする．全体の流れは，浸水範囲から通行困難道路を設定し，避難所までの経路を確認したうえで，自家用車のみの場合とデマンド交通バスを活用する場合を比較するものである．

表1．研究フェーズの位置づけ

| フェーズ | 目的 | 主な入力 | 作成予定の内容 |
|---|---|---|---|
| Phase 1 | 浸水時に利用できない道路を設定し，避難所までの経路を確認する | 浸水範囲，道路ネットワーク，出発地，避難所 | 閉鎖道路リスト，避難経路確認用データ |
| Phase 2 | 自家用車のみで避難する場合の交通流を設定する | Phase 1の閉鎖道路，SUMO道路ネットワーク，車両ルート | 自家用車避難シナリオ，交通流シミュレーション条件 |
| Phase 3 | デマンド交通バスを導入する場合の避難支援効果を比較する | Phase 2の基準シナリオ，バス需要候補，バス運行条件 | バス活用シナリオ，比較用評価指標 |

本研究で使用する主なデータとツールを表2に示す．各データに何が含まれており，研究でどのように活用するのかを整理する．

表2．主なデータ・ツールと本研究での役割

| 略称・用語 | 内容 | 本研究での使い方 |
|---|---|---|
| GSI KML | 国土地理院が公開した浸水範囲の時系列データである．KMLは地図上に線や面を表示するための地理情報ファイル形式である | 浸水範囲が時間とともにどの方向へ広がるかを把握する |
| A31a | 国土数値情報の洪水浸水想定区域データである．想定される浸水範囲を面データとして持ち，浸水深を段階的に示す浸水深コードを含む | 浸水深0.5m以上に相当する範囲を抽出し，道路閉鎖候補を作る |
| N03 | 国土数値情報の行政区域データである．市町村界を含む | 常総市および茨城県内対象市区町村の範囲を切り出す |
| P20 | 国土数値情報の避難施設データである．施設位置や対応する災害種別を含む | 洪水に対応する避難所を抽出し，目的地候補として用いる |
| 250m人口メッシュ | 250m四方ごとの人口集計データである | 浸水範囲内または周辺の居住者を出発地として設定する |
| GraphML | 道路を交差点などのノードと道路区間であるedgeとして保存する形式である | 避難経路検索とSUMOネットワーク変換の元データに使う |
| SUMO | Simulation of Urban MObilityの略で，道路ネットワーク上で車両を走行させる交通流シミュレータである[3][4] | 自家用車やバスを道路上で走行させるシミュレーションに使う |
| TraCI | PythonからSUMO実行中の車両や道路状態を操作する仕組みである | 時刻に応じた道路閉鎖や，閉鎖後の経路再探索を設定する |
| SUMO edge | SUMO内の道路区間を表すIDである | Phase 1で抽出した閉鎖道路をSUMO上の道路区間へ対応付ける |
| `joso.net.xml` | 常総市道路ネットワークをSUMO用に変換したファイルである | SUMO上で車両が走る道路として使う |
| `closure_timeline_sumo.json` | 時刻別に閉鎖する道路をSUMO edge IDで表したファイルである | TraCIで道路閉鎖を行う入力として使う |

道路閉鎖は，SUMOが自動的に計算するものではなく，浸水データから事前に設定する条件である．具体的には，A31aの浸水想定区域から浸水深0.5m以上に相当する範囲を抽出し，その範囲と道路リンクが重なる場合に，その道路を通行困難道路として扱う．これは，浸水深0.5m程度で自動車走行が危険になることが示されているためである[7][8]．

浸水時系列t0〜t7は，浸水範囲が広がる段階を表す時点である．本研究では，これらの時点をSUMO上の0〜21,600秒に対応付け，時間の経過に応じて道路閉鎖が増える条件を作成する予定である．道路が閉鎖された場合，SUMO上の車両は通行できる別経路を探索する設定とする．

## 3. 研究計画

本研究では，Phase 1からPhase 3までを段階的に行う．今回の中間発表では，実行済みの数値を示すのではなく，各Phaseで何を作成し，どのような条件で比較できるようにするかを報告する．

Phase 1では，浸水時に通行困難となる道路を抽出し，避難所までの経路を確認するための基礎データを作成する．出発地は250m人口メッシュを用いて設定する．ここでいう対象メッシュは，常総市全域の人口を表すものではなく，浸水範囲内またはその周辺に位置し，避難開始地点として扱うメッシュである．この対象メッシュを道路ネットワーク上の代表点へ対応付け，避難所までの経路確認に用いる．

避難所は，P20避難施設データのうち洪水に対応する施設を候補とする．洪水対応避難所とは，避難施設データ上で洪水災害への対応が示されている施設であり，すべての避難施設が洪水時の目的地になるわけではない．また，避難所が浸水想定区域内に含まれる可能性もあるため，浸水範囲との位置関係を確認し，目的地として利用できる条件を整理する．浸水区域内に含まれる住民については，対象メッシュから最寄りの利用可能な洪水対応避難所へ向かう想定で扱う．

Phase 2では，Phase 1で作成した閉鎖道路をSUMO edge IDへ変換し，SUMO上で時刻別に道路を閉鎖できるようにする．これは，浸水そのものをSUMOで計算するという意味ではなく，浸水データから作成した閉鎖条件をSUMOへ入力するという意味である．道路が閉鎖された場合には，TraCIを用いて車両に別経路を探索させる設定とし，自家用車のみで避難する基準シナリオを作成する．車両数は，常総市全体の人口や自動車保有台数をそのまま用いるのではなく，対象メッシュに含まれる人口をもとに設定する．

Phase 3では，既存のデマンド交通バスを避難支援に用いるシナリオを作成する．この段階では，自家用車のみの場合を基準として，バスを導入した場合に避難できる人数，未到着となる車両や住民，主要道路の混雑，バス輸送人数を比較できるようにする．徒歩避難，家族・近隣住民による送迎，福祉輸送，自治体バスなどは避難支援手段として重要であるが，本研究ではまずデマンド交通バスに対象を絞る．他の避難支援手段との比較は，研究範囲を広げる際の課題として整理する．

## 4. 今後の作業予定

今後の作業は，データ整理，経路確認，自家用車シナリオ作成，デマンド交通バスシナリオ作成の順に進める．

まず，GSI KMLとA31aを用いて浸水範囲を整理する．GSI KMLは浸水範囲の時間変化を把握するために用い，A31aは浸水深0.5m以上に相当する範囲を抽出するために用いる．次に，N03で対象地域を切り出し，P20から洪水対応避難所を抽出する．250m人口メッシュは，避難開始地点と対象人口を設定するために用いる．

次に，道路ネットワークと浸水範囲を重ね合わせ，通行困難道路を抽出する．抽出した道路は，Phase 1では経路確認用の閉鎖道路として用い，Phase 2ではSUMO edge IDへ対応付けて時刻別の閉鎖条件として用いる．これにより，静的な経路確認から動的な交通流シミュレーションへ接続できるようにする．

その後，自家用車のみの避難シナリオを作成する．このシナリオでは，出発地，目的地，車両数，出発時刻，道路閉鎖時刻，再経路探索の条件を整理する．特に，浸水開始と同時に全車両が出発するのか，出発時刻を分散させるのかは，シミュレーション条件として明確にする必要がある．

最後に，デマンド交通バスを導入する条件を設定する．バスの乗車対象者，乗降地点，目的地とする避難所，運行台数，経路選択方法を整理し，自家用車のみの場合と同じ指標で比較できるようにする．比較指標としては，到着人数，未到着人数，主要避難路の混雑，バス輸送人数などを検討する．

## 5. おわりに

本研究では，2015年鬼怒川氾濫を事例に，浸水時の道路閉鎖を考慮した避難シミュレーションの構築を計画している．今後は，浸水データ，道路ネットワーク，人口メッシュ，避難施設データを組み合わせ，自家用車避難の基準シナリオとデマンド交通バス活用シナリオを作成する．今回の発表では，そのために使用するデータ，シミュレーション条件，今後の作業手順を整理した．これにより，河川氾濫時におけるデマンド交通バスの避難支援手段としての活用可能性を検討する準備を進める．
