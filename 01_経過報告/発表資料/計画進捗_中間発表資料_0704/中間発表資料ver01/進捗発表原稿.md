### 2.2 研究背景・目的

```text
1. 研究背景・目的

本研究は、平成27年9月関東・東北豪雨に伴う鬼怒川氾濫を背景とする。2015年9月10日12時50分ごろ、茨城県常総市三坂町付近で鬼怒川左岸の堤防が決壊し、市域の広い範囲で浸水被害が発生した。河川氾濫時には、浸水によって道路が通行困難となるだけでなく、自家用車避難が集中することで混雑や逃げ遅れが発生する可能性がある。また、高齢者や自家用車を利用できない住民に対しては、デマンド交通バスなどを活用した避難支援の可能性を検討する必要がある。

本研究の目的は、浸水時の道路閉鎖を考慮した避難シミュレーションを構築し、自家用車のみで避難した場合と、今後デマンド交通バスを活用した場合を比較できる基盤を作ることである。今回の進捗発表では、Phase 1で実施した静的な避難経路検索と、Phase 2で実施したSUMO/TraCIによる自家用車避難の交通流シミュレーションについて報告する。
```

### 2.3 使用データとシミュレーション構成

```text
2. 使用データとシミュレーション構成

本研究では、浸水範囲、道路ネットワーク、行政区域、人口メッシュ、避難施設、自動車保有台数を用いる。浸水範囲には国土地理院の浸水推定範囲KMLおよび国土数値情報A31a浸水想定区域を用い、浸水深0.5m以上に相当する範囲と道路リンクが重なる場合、その道路を通行困難な道路として扱う。道路ネットワークはGraphML形式で取得し、Phase 2ではSUMOネットワークへ変換した。人口メッシュと自動車保有台数は避難車両の発生量を推計するために用い、避難施設データは目的地となる安全避難所の設定に用いる。

SUMO上では、実データをそのまま読み込むのではなく、実データから作成した派生データを入力として用いる。具体的には、道路ネットワークを `joso.net.xml` に変換し、出発地と避難所をSUMO edgeへスナップする。また、Phase 1で作成した道路閉鎖時系列をSUMO edge IDへ対応付け、TraCIにより時刻ごとに通行止めを反映する。これにより、車両走行、道路閉鎖、再経路探索、到着・未到着判定を時系列で評価する。
```

### 2.4 Phase 1：静的な避難経路検索

```text
3. Phase 1：静的な避難経路検索

Phase 1では、浸水範囲と道路ネットワークを重ね合わせ、通行困難となる道路を除外したうえで、出発地から避難所までの経路検索を行った。これは、道路閉鎖によって避難所までの経路が存在するかを確認する静的なネットワーク分析である。常総市を中心事例とし、その後、茨城県内の対象41市区町村へ拡張して、市区町村別の避難経路シナリオHTMLを生成した。

ただし、Phase 1では車両同士の混雑、停止、発車時刻、到着時間は扱わない。そのため、Phase 1の到達不可メッシュや到達不可人口は、道路ネットワーク上の経路存在性を示す指標であり、実際に車両が走行した場合の結果とは区別する必要がある。
```

### 2.5 Phase 2：SUMOによる自家用車避難シミュレーション

```text
4. Phase 2：SUMOによる自家用車避難シミュレーション

Phase 2では、Phase 1で作成した道路閉鎖条件をSUMO/TraCIへ接続し、自家用車のみで避難するシナリオAの交通流シミュレーションを構築した。SUMO 1.26.0を用い、道路ネットワーク上に車両エージェントを投入し、t0〜t7の閉鎖時刻に応じてTraCIでSUMO edgeを通行止めにした。道路閉鎖後は再経路探索を行い、車両が安全避難所へ到着できるか、また未到着や長時間停止が発生するかを記録した。

常総市では、small、10pct、fullの3種類の規模で実行した。smallは動作確認、10pctは主比較指標、fullは常総市詳細確認として位置づけた。また、茨城県内41市区町村についてはsmallおよび10pctを実行し、代表6市区町村でfullを補助的に実行した。
```

### 2.6 結果

```text
5. 結果

常総市シナリオAの実行結果を表2に示す。small試行では40台、10pct試行では120台がすべて到着した。full試行では1,001台のうち987台が到着し、14台が未到着となった。未到着14台は、閉鎖済みの出発edgeから発車できなかった車両として記録されており、本研究では逃げ遅れ候補として扱う。

また、主要避難路別の混雑指標を確認したところ、full試行では県道357号において最大137台、最大停止車両105台、最低平均速度1.64m/sが記録された。国道294号でも最大61台、最大停止車両7台が記録され、自家用車避難が集中した場合に一部路線で速度低下や停止が発生することを確認した。

全41市区町村の10pct試行では、23,054台すべてが到着し、主指標上の逃げ遅れは発生しなかった。ただし、この結果は今回のモデル仮定下での結果であり、実災害時の安全性を保証するものではない。
```

### 2.7 考察・今後の予定

```text
6. 考察・今後の予定

Phase 1とPhase 2は、どちらも浸水に伴う道路閉鎖が避難へ与える影響を扱うが、評価している内容は異なる。Phase 1は閉鎖道路を除外した場合に避難所までの経路が存在するかを調べる静的分析であり、Phase 2は車両をSUMO上で走行させた場合の到着、未到着、混雑を評価する動的分析である。そのため、Phase 1の到達不可人口とPhase 2の未到着車両数を同じ単位として直接比較しない。

Phase 2により、自家用車のみで避難した場合の交通流ベースラインを構築できた。一方で、Phase 2では一斉出発、6時間圧縮、安全避難所への避難、10pct試行を主指標とするなどの仮定を置いている。また、車を持たない住民や高齢者の避難支援、バスの乗降や待ち時間はまだ扱っていない。

今後のPhase 3では、デマンド交通バスを導入したシナリオBを作成し、Phase 2の自家用車のみの結果と比較する。比較指標としては、到着台数、未到着台数、逃げ遅れ候補、主要避難路の混雑、バス輸送人数を用いる予定である。
```

### 2.8 結論

```text
7. 結論

本研究では、2015年鬼怒川氾濫を背景に、浸水時の道路閉鎖を考慮した避難シミュレーションを構築している。Phase 1では静的な避難経路検索を行い、Phase 2ではSUMO/TraCIを用いた自家用車避難の交通流シミュレーションを実装した。常総市full試行では1,001台中987台が到着し、14台が閉鎖済み出発edgeの影響を受けた。これらの結果を、今後デマンド交通バスを導入するPhase 3の比較基準として用いる。
```

## 6. 想定質問への回答文

詳細版は `中間発表_想定質問詳細.md` にQ1からQ36までカテゴリ別に整理した。`04_プログラム/output/faq.html` も同じ質問群をサブセクター付きで実装している。

### Q1. SUMOは何のデータをもとに動いているのか。

```text
道路ネットワーク、人口メッシュ、自動車保有台数、避難施設データ、浸水による道路閉鎖時系列をもとにしています。ただし、これらをそのままSUMOへ入れるのではなく、道路はSUMOネットワーク、出発地と避難所はSUMO edgeにスナップしたCSV、道路閉鎖はSUMO edge IDへ変換したJSONとして入力しています。
```

### Q2. SUMOで浸水を再現しているのか。

```text
SUMO自体で浸水を計算しているわけではありません。浸水KMLやA31a浸水想定区域から、どの道路がどの時刻に通行困難になるかをあらかじめ作成し、それをTraCIでSUMO上の道路閉鎖として反映しています。
```

### Q3. full試行で未到着14台とは何か。

```text
常総市full試行では、1,001台のうち987台が到着し、14台が未到着でした。この14台は、閉鎖済みの出発edgeから発車できなかった車両として記録されています。そのため、単純なプログラムエラーではなく、今回の閉鎖条件下での逃げ遅れ候補として扱っています。
```

### Q4. 10pct試行で逃げ遅れが0なら、安全といえるのか。

```text
安全を保証するものではありません。10pct試行は全メッシュを残しつつ車両数を縮小した比較用の条件です。一斉出発、6時間圧縮、安全避難所固定などの仮定もあるため、結果は今回のモデル条件下での自家用車避難ベースラインとして扱います。
```

### Q5. Phase 3で何を比較するのか。

```text
Phase 3では、Phase 2の自家用車のみのシナリオAに対して、デマンド交通バスを追加したシナリオBを作成します。到着率、未到着、逃げ遅れ候補、主要避難路の混雑、バス輸送人数を比較し、バス活用によってどの程度避難支援効果があるかを評価する予定です。
```

### Q6. SUMOシミュレーションはどのような時間軸で行っているのか。

```text
Phase 2では、実際の浸水時系列t0〜t7をSUMO上の6時間、つまり0〜21,600秒へ線形圧縮しています。
SUMOの0秒は車両の出発開始時刻であり、浸水時系列のt0そのものではありません。
最初の閉鎖時点であるt0はSUMO上では789秒、最終時点t7は21,600秒に対応します。

現在のHTMLアニメーションでは、small試行と10pct試行の車両位置を表示しています。
small試行は619秒、10pct試行は615秒で全車両が到着しており、最初の道路閉鎖t0=789秒より前に車両移動が終わっています。
そのため、アニメーション上ではt0以降の道路閉鎖後の動きが見えにくい状態です。

発表では、現在の可視化は車両移動とSUMO連携を確認するための表示であり、閉鎖後の交通挙動を説明するにはfull試行の可視化、または閉鎖時系列と車両軌跡を同時に確認できる表示が必要であると説明します。
```

### Q7. 避難開始地点はどのように決めているのか。

```text
避難開始地点は、250m人口メッシュの代表点をもとに決めています。
人口が存在するメッシュを出発地として扱い、そのメッシュ代表点の緯度経度を最寄りのSUMO edgeへスナップしています。
SUMO上では、スナップ先のedgeから車両を出発させます。

常総市Phase 2では、出発地メッシュ40地点を設定し、40地点すべてがSUMO edgeへ対応しています。
車両台数は人口から世帯数を近似し、full試行ではceil(total_pop / 2.3)、10pct試行ではその1/10、small試行では人口があるメッシュにつき1台として設定しています。

したがって、現状は各世帯の住所から出発させているのではなく、250mメッシュ単位の代表地点から車両を発生させるモデルです。
```

### Q8. なぜPhase 2の対象地域を常総市にしているのか。

```text
Phase 2では、2015年鬼怒川氾濫で被害の中心となった常総市を対象にしています。
Phase 1では茨城県内の複数市町村へ対象を広げましたが、Phase 2ではSUMOによる交通流シミュレーションを行うため、まず実災害との関係が明確で、道路、人口、避難所、浸水時系列をそろえやすい常総市を基準地域にしています。

つまり、Phase 2の目的は対象範囲を広げることよりも、実データからSUMO入力を作成し、自家用車避難の交通流ベースラインを構築することです。
常総市で方法を固定したあと、Phase 3以降でバス追加や他地域展開を検討します。
```

### Q9. 道路閉鎖の基準はどのように決めているのか。

```text
道路閉鎖は、浸水深0.5m以上を基本条件として設定しています。
国土数値情報A31aのwaterDepth属性では、コード2以上が0.5m以上の浸水を示すため、この条件を道路通行が困難になる目安として採用しました。

そのうえで、浸水ポリゴンと道路リンクを空間的に重ね合わせ、該当する道路を時刻別の閉鎖候補として扱っています。
SUMOでは、その閉鎖候補をSUMO edge IDへ変換し、TraCIで時刻に応じて通行不可にしています。

ただし、実際の通行可否は車種、流速、道路構造、現地判断にも左右されるため、0.5m以上という条件は実災害を完全に再現するものではなく、比較シミュレーションのための統一した閉鎖条件として扱っています。
```

### Q10. 避難所はどのように選んでいるのか。

```text
避難所は、国土数値情報の避難施設データをもとに、洪水対応の避難施設を対象にしています。
Phase 2では、避難所の位置をSUMOネットワーク上の最寄りedgeへスナップし、車両の目的地として使用しています。

また、浸水リスクがある避難所をそのまま目的地にすると、現実的ではない避難先を選んでしまう可能性があります。
そのため、Phase 2では避難所の安全性を確認し、避難先として利用する候補を固定しています。

現在のモデルでは、各出発地から到達可能な避難所のうち、道路距離が近い避難所を目的地として扱っています。
```

### Q11. なぜsmall、10pct、fullの3種類の試行を行っているのか。

```text
small試行は、各出発地メッシュから1台ずつ出発させ、SUMOネットワーク、経路、可視化が正しく動くかを確認するための試行です。
10pct試行は、全出発地メッシュを残したまま車両数を縮小し、交通流の傾向を軽い計算量で確認するための試行です。
full試行は、人口から推定した車両台数を用いて、Phase 2の主結果として扱う試行です。

台数については、small試行は対象となる出発地メッシュが40地点あるため、各メッシュ1台として40台にしています。
10pct試行は、full試行の車両台数を各メッシュごとに約1割へ縮小し、0台にならないように切り上げているため、合計120台になっています。
full試行は、各メッシュの人口を1世帯あたり2.3人で割って世帯数を近似し、各メッシュごとに切り上げた車両台数の合計として1,001台になっています。

この3段階に分けることで、まず小規模で動作確認を行い、その後に本格的な車両数で結果を確認できるようにしています。
```

### Q12. 車両台数はどのように決めているのか。

```text
車両台数は、人口メッシュの人口をもとに世帯数を近似して決めています。
具体的には、1世帯あたり2.3人と仮定し、full試行では各メッシュの人口を2.3で割り上げた値を車両台数としています。
10pct試行ではfull試行の約1割、small試行では人口があるメッシュごとに1台として設定しています。

これは、実際の各世帯の車両保有状況や避難開始行動を直接観測したデータではありません。
そのため、結果は「人口分布にもとづく自家用車避難の近似モデル」として解釈します。
```

### Q13. 目的地となる避難所は各車両ごとに途中で変わるのか。

```text
現状のPhase 2では、各出発地に対して避難先を事前に決め、その避難所へ向かう経路をSUMO上で走行させています。
そのため、運転者が途中で避難所を変更したり、混雑を見て自発的に別の避難先を選んだりする行動はまだ入れていません。

道路閉鎖が発生した場合は、SUMO/TraCI上で通行できないedgeを反映し、再経路探索や未到着の判定を行います。
ただし、避難者の意思決定そのものをモデル化しているわけではないため、この点はPhase 3以降の改善点です。
```

### Q14. 6時間に圧縮した時間設定は結果に影響しないのか。

```text
時間圧縮は結果に影響します。
Phase 2では、t0〜t7の浸水時系列をSUMO上で扱いやすくするため、6時間に線形圧縮しています。
これは、浸水の進行と交通流を同じシミュレーション内で確認するための設定です。

ただし、圧縮すると、実時間での避難余裕や交通量の広がり方とは異なる可能性があります。
そのため、Phase 2の結果は実時間を完全再現した予測ではなく、同じ時間設定のもとでシナリオAと今後のシナリオBを比較するための基準として扱います。
```

### Q15. Phase 2の結果を考察に使うとき、どこまで言えるのか。

```text
Phase 2の結果から言えるのは、設定した出発地、車両台数、避難所、道路閉鎖時系列のもとで、自家用車避難を行った場合に、どの程度到着できるか、どの道路に交通が集中するか、どの条件で未到着や停止が発生するかです。

一方で、実際の避難行動、出発時刻のばらつき、信号制御、道路規制、避難者の判断、徒歩避難や公共交通との混在までは十分に再現していません。
したがって、Phase 2の結果は実災害の再現値ではなく、Phase 3でデマンド交通バスを追加した場合と比較するための自家用車避難ベースラインとして使います。
```
