# 中間発表予稿の構成と記述の定義

作成日：2026年11月6日  
対象：2026年12月5日中間発表のWord予稿  
目的：修正前の予稿と先生の添削を基に、章構成、各節に書く内容、説明の順序、修正時の確認事項を定める。

本書は原稿を修正するための作業基準である。先生の明示指示と、その指示を具体化するための構成案を区別する。研究条件や結果の採用を変更する文書ではなく、構成案について先生の了承を得たことも意味しない。

本書で用いる区分は次のとおりである。

- **先生の指示**：添削版に赤字・取り消し線・コメントとして明示された内容。
- **構成案・記述方針**：先生の指示を原稿へ反映するために、本書で提案する編集上の具体化。
- **要確認**：研究の元資料や確定結果との照合が必要な内容。原稿に書いてあるだけでは確認済みとしない。

本文の構成・説明は本書、Wordの数値的な書式は既存の形式定義を参照する。研究上の事実・数値・解釈は研究の正本で確認する。本書の作成だけを理由に、原稿の内容基準日を更新したり、後続系列の結果を追加したりしない。

## 2. 全体構成

### 2.1 先生の指示

「現状の分析」を示した後、「支援政策の提案」へ進む。支援政策は、先生が示した次の2つの視点でまとめ直す。

1. デマンド交通活用による周辺道路渋滞緩和
2. デマンド交通による移動困難者支援

### 2.2 章立ての構成案

以下の章番号、小見出し、最終章の名称は、本書で具体化した作業案である。

```text
題目　デマンド交通の災害時活用政策提案
所属・氏名　眞坂研究室　氏名：古賀玲次

1. はじめに
2. 現状の分析
   2.1 対象地域と使用データ
   2.2 静的分析による避難所への到達可能性
3. 支援政策の提案
   3.1 デマンド交通活用による周辺道路渋滞緩和
   3.2 デマンド交通による移動困難者支援
4. まとめと今後の課題
参考文献
```

説明は「研究の背景と着眼点 → 支援政策を導入する前の課題 → 2つの支援政策 → 検証で分かったことと未解決事項」の順につなぐ。静的分析、動的計算、固定経路バス、予約型配車を研究の実施順に並べるだけの構成にしない。

2ページに収めるために削る場合も、対象範囲、主要指標の分母、比較条件、結果、解釈の限界は残す。細かな実装手順や全試行の詳細を優先して本文を埋めない。

## 3. 各章に書く内容

### 3.1 はじめに

デマンド交通の役割と継続上の課題を示したうえで、災害時の活用に着目した研究目的を書く。

- 文献に基づく一般的な背景と、本研究の着眼点を分ける。「新たな価値が求められている」を出典のある一般論として書かない。
- 先生の書き換えを踏まえ、維持継続のために新たな価値を見いだすことの重要性から、本研究の災害時活用へつなぐ。
- 目的は「災害時の避難支援への活用可能性を検討する」とし、具体的な対象事例として鬼怒川氾濫と常総市を説明する。
- 自動車避難時の混雑など、現状分析の導入となる説明は2章へ置く。
- 本稿の紹介文も新しい章構成に合わせる。予約型配車だけを予稿全体の到達点として紹介しない。

### 3.2 現状の分析

支援政策を検討する前提として、対象地域と避難上の課題を説明する。

**2.1 対象地域と使用データ**では、対象地域、解析範囲、浸水・道路・人口・避難所のデータと用途を順に書く。

- 「行政区域で切り出した範囲」では、どの行政区域を、何のデータの切り出しに使ったかを明示する。実際の処理を確認するまで「常総市全域」などと補わない。
- 域外への流出入を扱わない条件は、対象範囲の説明につなげて書く。
- 対象者は各分析の説明箇所で定義する。「各段階の分母が異なる」という抽象的な注意だけで済ませない。

**2.2 静的分析による避難所への到達可能性**では、対象、判定方法、結果、意味の順に書く。

- 旧原稿の道路網12,860区間、40区画・2,257人、避難所19施設が、それぞれ何の範囲・単位を表すか確認する。「区画」が人口メッシュを指すかも確認する。
- 道路網全体の区間数と、浸水にかかる区間数、閉鎖後に残る区間数を混同しない。先生の例文も数値の定義を確認してから具体化する。
- 浸水の8時点と、閉鎖道路168本から764本への変化の関係を元資料で確認する。各時点の道路網を別々に固定して経路探索したのであれば、その方法を明記し、車の移動を追う動的計算との違いが伝わるようにする。
- 結果には、誰が、どの条件で、何人または何区画、避難所へ到達する経路を持たなかったかを書く。
- 旧原稿の約4割という結果を、市全体の被災割合、実際の逃げ遅れ人数、自家用車を利用できない人の割合へ読み替えない。

### 3.3 支援政策の提案

章の冒頭で、現状分析を踏まえ、デマンド交通の災害時活用を2つの視点から検討すると宣言する。静的な経路の有無だけから、渋滞の発生や移動困難者の人数まで確認できたとは書かない。

**3.1 デマンド交通活用による周辺道路渋滞緩和**では、政策の狙い、比較・分析の方法、確認できた結果、残る課題を書く。

- 先生の赤字指示に従い、デマンド交通を用いない場合の既存の渋滞予測結果を探し、元run・設定・指標・結果の採用可否を確認する。
- SUMOやTraCIを使って何を実装したかだけで終わらず、その計算から何が観測・確認できたかを示す。
- デマンド交通を用いない条件だけの結果は、渋滞の現状を示す材料として扱う。渋滞緩和の効果を述べるには、支援あり・なしで比較できる条件と渋滞の指標が必要である。
- 300秒後に車を先へ移す設定などの制約は、結果の意味に結び付けて説明する。信頼できる比較結果が確認できなければ、政策目的と未検証の課題を明示する。
- 先生の「結果をここにのせる」という指示文は、提出本文には残さない。結果があるはずだという推測で数値を補わない。

**3.2 デマンド交通による移動困難者支援**では、対象者の定義、人数の算出、支援と比較の条件、結果、次の課題を書く。

- 自家用車を利用できない3,255人について、元人口から対象者を絞る過程、使用した属性・割合・仮定、高齢者935人と非高齢者2,320人の内訳の根拠を確認する。
- 「自家用車と迎えの車」は、誰が誰を迎えるモデルか、利用できる人とできない人をどう設定したかまで説明する。根拠なく家族・知人による送迎に置き換えない。
- 固定経路バスの条件A・Bは、共通条件と追加した支援を先に示してから結果を書く。避難完了率を渋滞緩和の直接的な指標として扱わない。
- 結論は「本モデルの分解能では方向性のある差を検出できなかった」を保持する。中央値や正負の組数だけで、有利、不利、効果なし、同等とは結論しない。
- 15通りの差を掲載する場合は、同じ試行を組み合わせた差であり、独立した15試行ではないことを示す。
- 予約型配車は、先生が保留とした部分である。固定経路バスの課題との接続を整理したうえで、掲載位置と説明量を再検討する。先生の了承済みの実験設計として扱わない。

### 3.4 まとめと今後の課題

現状分析で分かったことと、2つの政策について確認できた範囲を短くまとめる。実装できたこと、モデル内で観測されたこと、政策効果を検証できたことを区別する。

予約型配車や大型バスなどの後続検討は、確定した結果と分けて記す。旧原稿の「これからの研究」は内容基準日時点の記述として扱い、現在の研究進捗を確認せずに未来形・完了形を変更しない。

## 4. 文章と図表の書き方

### 4.1 説明の順序

各分析・比較は、原則として次の順序で説明する。

1. **目的**：何を確かめるための分析か。
2. **対象と条件**：どこで、誰を対象に、どの条件で調べたか。
3. **方法**：何を変え、何を固定し、何を判定・比較したか。
4. **結果**：どの指標で何が分かったか。
5. **解釈と限界**：その結果から言えることと、確認できていないこと。

短い段落でも目的・対象・結果の関係を残す。「実装した」「記録した」という作業報告だけで終えない。結果が未確認の場合は、その状態を作業メモに記し、提出本文の結論を推測で埋めない。

### 4.2 表現と数値

- である調、句読点「，」「．」に統一する。先生の赤字中の句読点も、本文へ反映する際にそろえる。
- 見出しは内容を示す。「これまでの研究」「これまでから変える点」など、研究履歴だけを表す見出しは置き換える。
- 「到達可能性」は道路網上の経路の有無、「避難完了率」はシミュレーションの完了判定として、定義と条件を添えて使い分ける。
- 人数、区画数、道路区間数、車両数、予約件数を区別する。異なる分析の分母や対象範囲を説明なしに並べない。
- 割合には対象と分母、差には単位を示す。割合の差は、必要に応じて「ポイント」で表す。
- 現実の災害の事実、モデル上の仮定、計算結果、政策提案を同じ確かさで断定しない。
- 「約4割だからバスで救える」など、分析で確かめていない因果関係や実現性を補わない。

### 4.3 図表と参考文献

- 図表は、本文の問いと結果を伝えるために選ぶ。現行の図1は固定経路バス比較の資料であり、渋滞緩和を示す図とは扱わない。
- 本文で図表番号に触れ、対象・条件・指標・単位が分かる図題・注記を付ける。異なる実験系列の結果を同条件の比較に見せない。
- 構成変更によって本文の引用初出順が変わる場合は、本文と参考文献一覧の番号を対応させる。既存文献のURL・閲覧日を確認なく更新しない。
- 最終的な図表の数、掲載寸法、改ページはWord上で確認し、2ページに収まるよう調整する。

## 5. 先生のコメントとの対応

コメントIDは添削Word内部のID（0〜9）である。以下の対応は修正作業の定義であり、対応完了の記録ではない。

| ID | 指摘の要旨 | 対応する箇所・作業 |
| --- | --- | --- |
| 0 | 新たな価値は一般論ではなく、本研究の着眼点 | 1章で背景と研究の着眼点を分ける |
| 1 | 行政区域で切り出した範囲とは何か | 2.1で区域名、切り出したデータ、境界条件を明記する |
| 2 | 分母の違いの説明で何を伝えたいのか不明 | 各分析の対象を、その分析の説明箇所で定義する |
| 3 | 道路網、40区画、2,257人の関係を明確にする | 2.2で対象範囲・単位を確認し、地域から対象者へ順に書く |
| 4 | 静的分析なのに閉鎖道路が増えるのはなぜか | 2.2で浸水時点と各時点の経路探索の関係を確認・説明する |
| 5 | 2つの政策の視点でまとめ直す | 3章を渋滞緩和と移動困難者支援で構成する |
| 6 | 動的計算で結局何が分かったのか | 3.1で既存の渋滞予測結果と、その解釈の範囲を示す |
| 7 | 3,255人を出すまでを詳しく書く | 3.2で人口からの算出過程と仮定を説明する |
| 8 | 誰が誰を迎えるのか、現実的か | 3.2で迎えの車の実際のモデル設定と限界を説明する |
| 9 | 予約型配車の章はコメントを保留 | 3.2または4章への接続を再検討し、再確認が必要な部分として扱う |

赤字・取り消し線による指示も反映する。導入の書き換え、「現状の分析」「支援政策の提案」への変更、避難上の問題を現状分析へ移すこと、既存の渋滞予測結果を掲載することを確認する。添削は変更履歴ではなく直接の文字装飾であるため、旧文と修正文を両方残さない。

## 6. 修正の手順と完了条件

1. **根拠確認**：解析範囲、静的分析の時点別条件、渋滞予測結果、3,255人の算出、迎えの車の設定を元資料で確認する。
2. **本文修正**：本書2.2の章立てに沿って並べ替え、各節を目的・対象・方法・結果・限界の順で書き直す。掲載できる結果がない部分は、検証済みの成果として書かない。
3. **対応確認**：コメント10件と赤字・取り消し線の指示について、反映箇所と未解決事項を確認する。
4. **Word確認**：既存の形式定義に従って組み、2ページ、図表の可読性、引用番号、不要な旧文・指示文の残存を確認する。

本文修正の完了条件は、対象と比較条件を読者が追え、各分析で何が分かったかが示され、2つの政策について確認済みと未検証の範囲が明確であることとする。先生による再確認の完了とは区別する。

- [ ] 解析範囲と各分析の対象者を具体的に説明した。
- [ ] 静的分析の時点と道路閉鎖の関係を説明した。
- [ ] 渋滞予測の既存結果を確認し、掲載可否と解釈の範囲を判断した。
- [ ] 3,255人の算出過程と迎えの車の設定を根拠に沿って説明した。
- [ ] 2つの政策に沿って構成し、実装の説明だけで終わる節をなくした。
- [ ] 固定経路バスの結論と、モデル結果の解釈の限界を保持した。
- [ ] 予約型配車の保留を解消するための説明を整理した。
- [ ] 本文・図表・参考文献を照合し、Wordの2ページ表示を確認した。
