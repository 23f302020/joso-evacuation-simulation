### 8-3. テスト結果と判明した問題

構文チェック（`py_compile`）は全4ファイル成功。実行テストでは環境依存ライブラリ未導入のため停止（コード自体の問題ではない）。結果を `04_プログラム/テスト結果_phase1_01.md` に記録した。

**発見した空間照合バグ（0 edges closed 問題）：**

実際に c3・e1 の出力を用いて i1 を実行したところ、全タイムスタンプで「0 edges closed」と出力された。原因調査の結果、2段階の問題が判明した。

| 問題 | 原因 | 影響 |
|------|------|------|
| 問題1 | KML LineString に 10m バッファを付けても A31a ポリゴンと交差しない | `build_flood_polygons` が空の GeoDataFrame を返す |
| 問題2 | A31a グリッドセルが 5〜20m 四方の極小ポリゴン。OSM 道路中心線がセル間の隙間を通過 | sjoin で道路エッジが全て非交差と判定される |

### 8-4. 採用した修正アプローチ（案2+3複合）

**e1_load_flood_data.py の修正（問題1への対策）：**

KML の LineString バッファ（10m）による polygon 化を廃止し、各時点の全 LineString の **`union_all().convex_hull`** を浸水エンベロープとして採用（案2）。凸包内に A31a が 0 件の場合は A31a 全体をフォールバック採用（案3）。

```python
# KML 全ジオメトリの凸包を浸水エンベロープとして使用
kml_hull = kml_gdf.geometry.union_all().convex_hull
kml_envelope = gpd.GeoDataFrame(geometry=[kml_hull], crs=a31a.crs)
joined = gpd.sjoin(a31a, kml_envelope, how="inner", predicate="intersects")
result = a31a.loc[joined.index.unique()].copy()
if len(result) == 0:
    result = a31a.copy()  # フォールバック（案3）
```

**i1_spatial_join.py の修正（問題2への対策）：**

投影 CRS（EPSG:6690 / JGD2011 UTM54N）で浸水ポリゴン全体を **30m バッファ**してから sjoin を実施。30m = グリッド離散化誤差（最大 10m）＋車道幅余裕。

```python
_CRS_METRIC = "EPSG:6690"
_FLOOD_BUFFER_M = 30
flood_buffered = (
    gpd.GeoDataFrame(
        geometry=[flood.to_crs(_CRS_METRIC).geometry.union_all().buffer(_FLOOD_BUFFER_M)],
        crs=_CRS_METRIC,
    ).to_crs(flood.crs)
)
hit = gpd.sjoin(base[...], flood_buffered[...], predicate="intersects", how="inner")
```
