```python
# KML 全ジオメトリの凸包を浸水エンベロープとして使用
kml_hull = kml_gdf.geometry.union_all().convex_hull
kml_envelope = gpd.GeoDataFrame(geometry=[kml_hull], crs=a31a.crs)
joined = gpd.sjoin(a31a, kml_envelope, how="inner", predicate="intersects")
result = a31a.loc[joined.index.unique()].copy()
if len(result) == 0:
    result = a31a.copy()  # フォールバック（案3）
```

**i1_spatial_join.py の修正（問題2への対策）：**

### 10-3. 残っている課題

コミットコメントに記載の通り、現状では全タイムスタンプで到達不可メッシュ数が一定となっている。封鎖なし（`closure=[]`）では到達不可 0 になるため封鎖の影響自体は出ているが、時系列変化が見られない。

原因と対応方針の選択肢：

| 選択肢 | 内容 | 影響 |
|-------|------|------|
| A（累積封鎖） | 浸水ポリゴンを時点ごとに累積扱いにする | 時間が進むほど封鎖が増え到達不可が増加する |
| B（浸水範囲拡張） | 出発地の対象メッシュを浸水エリア外まで広げる | より多くの出発地を扱い変化が出やすくなる |

どちらを採用するかは研究のモデル設定（実際の洪水進行をどう扱うか）に関わるため、**指導教員への確認が必要**。

**→ 採用方針：選択肢A（累積封鎖）を採用。**
実際の鬼怒川氾濫（2015/09/10〜09/16）は約1週間継続しており、一度浸水した道路は期間中ほぼ回復しなかった。この実態に合致するため累積封鎖を採用する。`i3_route_search.py` の修正後、指導教員に事後報告する予定。

---

#### 【補足】なぜ到達不可数が変化しないのか — 具体的な仕組み

**本来期待される動作：**

洪水は時間とともに広がるため、時刻が進むほど封鎖される道路が増え、避難できなくなるメッシュも増えていくはずである。

```
t=0（破堤直後）: 封鎖15本 → 到達不可 X 件
t=1            : 封鎖31本 → 到達不可 X+α 件（増加するはず）
...
t=7（最終）    : 封鎖33本 → 到達不可 X+β 件（さらに増加するはず）
```

**現在の動作（問題）：**

全8タイムスタンプで到達不可件数が同じ値のまま変化しない。

**原因 — 出発地（origin）が固定されている：**

現在のコードでは、出発地メッシュを **t=0 の浸水ポリゴン** と重なるセルのみを使って一度だけ決定している。

```python
# i3_route_search.py の main() より
first_flood = flood_dict[config.KML_TIMESTAMPS[0]]   # t=0 の浸水ポリゴンのみ使用
origins = load_mesh_origins(config.MESH_FILE, first_flood)  # ← 以後 変わらない
```

この「出発地の固定」と「封鎖エッジ数が少ない」という2つの要因が重なることで、以下の状況が生じる。

| 要因 | 詳細 |
|------|------|
| 出発地が t=0 基準 | t=0 の浸水範囲は小さい（封鎖15本相当）ため、選ばれるメッシュ数が少ない |
| 封鎖エッジ数の変化幅が小さい | t=0〜t=7 でも封鎖エッジは15〜33本（道路網全体の12,860本に対し0.3%未満） |
| 迂回路が常に存在する | 封鎖エッジ数が少ないため、t=0 時点の出発地メッシュからは全タイムスタンプで避難所への迂回ルートが見つかる |

その結果、封鎖数が変化しても到達不可件数は変わらないという状態になっている。

**各選択肢が何を変えるか：**

**選択肢A（累積封鎖）** — 「洪水は引かない」という現実に合わせるアプローチ

```
現在: t=3 では「t=3 の浸水範囲だけ」を封鎖対象とする
案A:  t=3 では「t=0 + t=1 + t=2 + t=3 の全浸水範囲」を累積して封鎖する
```

過去に浸水した道路を累積的に封鎖し続けることで、時刻が進むほど通行不能区間が増え、到達不可件数の増加が現れる。ただし「洪水は一度浸水したら絶対に引かない」という前提になるため、その妥当性を研究内で説明する必要がある。

**選択肢B（浸水範囲拡張）** — 出発地の定義を広げるアプローチ

```
現在: 出発地 = t=0 の浸水エリア内のメッシュのみ（浸水被害を受けた住民）
案B:  出発地 = 常総市全域（または浸水リスクエリア全体）のメッシュ
```

浸水エリア外にいる住民も避難者として含めることで、時刻ごとに異なる封鎖パターンの影響が出やすくなる。ただし「浸水していない住民も自発的に避難する」という研究上の前提が追加されるため、その根拠を説明する必要がある。
