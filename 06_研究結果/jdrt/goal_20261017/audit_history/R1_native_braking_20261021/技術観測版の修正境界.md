# native診断の観測追加・技術再登録の境界

2026-10-21。設計候補であり、現行configの切替・新READY・core開始・旧runの採用を意味しない。

## 現在の証拠

`diagnostic_contract_real01.json`は元R1の圧縮一次CSVから再読した3時点、原ログ、同じnative binaryと同じcar XMLを使った隔離API証拠、compiled configのepsilon、公式native sourceの警告式を照合した。数式上はDIAGNOSTIC_MATCH。人工契約8試験と、実データのメモリ上の7改変拒否を確認した。チェッカーは一致時も常にcore_adoption_permitted=falseである。

元R1にはemergencyDecelの直接観測がなく、隔離API値の転用にはsource/configからの推論が残る。また、固定pairは警告を再現せず車軌跡が一致した。したがって、元runの未知警告ゲートを解除せず、INVALID_PRESERVEDを維持する。数式一致を安全性・唯一の原因・原研究runの新規合格と呼ばない。

## 変更する候補と変更しない条件

| 項目 | 技術版での扱い |
|---|---|
| 車両の緊急減速度 | nativeの実値を一次観測へ追加。4.5/9などを結果から入力値へ埋め込まない。車種/物理パラメータを変更しない |
| nativeコマンド・版の同定 | 実引数と登録IDをmanifestへ残す。従来のsemi-implicit Eulerと警告threshold既定値を明示し、既定値依存を監査可能にする |
| 急減速ログ | 当該actorの連続3時点、実native制約、車線/phase/時計、速度差、距離、native式と表示精度をすべて照合する汎用分類。actor IDや警告文だけを許可する仕組みにはしない |
| 判定不能 | 未知形式、欠損、曖昧な対応、制約逸脱、未対応native版、SHA差は従来どおりINVALID・保全・後続停止 |
| その他の禁止条件 | Error・collision・teleport・gridlock、会計差、二重移動、閉鎖後進入、曖昧遷移等0件を維持。idle等の既存fixtureが要求する急減速なし条件も維持 |
| 研究条件 | 需要、供給、徒歩能力/予算、受付/取消/乗降、予測、洪水閾値、施設/退出、終点、比較順・70セル・5seed、主要/副指標・分母を変えない |
| 既存採用R0 | 旧版の1件として台帳・run・実装・config・検証を保全し、新主比較へ転用しない |
| 新比較の版 | 別workspace・新台帳・新IDで全70を同一共通5実装へそろえる。旧READYを流用しない |

PAP §8はError等を0件としているが、一般の道路走行でnativeが出す急減速Warningを一律0件とは記載していない。現在の停止は、原ログを根拠に分類できなかった技術ゲートによる。予定する修正は、物理モデルを緩めて結果を通すことではなく、同じnativeの制約を一次データで検証可能にする観測・検証実装の補完である。この範囲はAGENTS §0/§7の技術作業権限として準備する。

一方、衝突や制約逸脱も許可する、観測欠損を許す、ログを削除する、未知警告を一括許可する、主指標/比較/除外規則を変更する案は含めない。その必要が生じた場合は、根拠・代替・影響を整理しユーザーの明示判断へ戻す。新規観測が入らない旧R1を後から合格へ変更する権限も追加しない。

## 実装・切替前に残る作業

1. `candidate_nativeaudit_v2_parameters.json`と`candidate_nativeaudit_v2_scope.json`を使い、変更をI/O・登録識別・監査観測へ限定する。研究条件の全セクションと70セル/seedの同一性は機械照合済み。現在のconfigは未変更、新workspaceは未作成。
2. native購読へemergencyDecelを追加し、車両actor行へ保存する。欠損/非有限/非正値を失敗にする。型・clock・状態が変わった境界を自動補完しない。
3. 独立actor監査で原ログの対象だけ連続3時点を保持し、raw上限に基づく一般分類を既存validatorへ実装する。prototypeの数値整合だけで採用しない。source/binary/options/記録schemaと既存の全ゼロ条件も拘束する。丸め境界や初期/取消/再出庫など対応不能な場合は推測で通さない。
4. 現行5ファイル/config/旧採用文書を正確に保全し、技術再登録の変更理由と新IDを明記する。旧台帳は編集せず、新台帳に旧セルをコピーしない。
5. 必要な対象試験・反証・current全26統合・全14smoke・独立preflight/G6 source監査を行う。native binaryが同じことと、current controller/validatorの証拠が新しいことを区別する。旧証拠のSHA付替えをしない。
6. 既存07監視の対象へ新workspaceを加える場合は旧対象/イベントを保全し、既存タスクのみでsource/config/PIDを確認する。新monitorやAI heartbeatは作らない。新READYと1セル容量を確認した後だけ、専用CLIで最初の新coreを開始する。

新しい未解決失敗が生じたらその原本と理由を残し、条件を変更して合格を作らない。全70と独立分析、資料不足・限界・全体文書の整合が終わるまで最終goalは未完である。
