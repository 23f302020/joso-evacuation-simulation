# 独立シミュレーション監視

研究実行器を変更せず、チャットから独立してWindows上で監視する。運用・検証記録は[導入タスク](../05_タスク管理/jdrt/独立監視システム_導入タスク.md)。研究の現在地・開始許可は引き続き`context.md`と専用研究CLIを正本とする。

## 動作

| 処理 | 間隔・契機 |
|---|---|
| 既知の実行中PIDの終了確認 | Windowsプロセスハンドルで基準1秒（処理時間により遅れる） |
| 新規manifest発見、状態・progress・ログ追記確認 | 10秒ごと |
| 孤立RUNNINGの通知 | 終了後のmanifest再読と3秒の猶予後 |
| 停滞の疑い | シミュレーション時刻が10分間不変。heartbeat時刻更新だけでは解除しない |
| Codex診断 | 新規イベント時だけ。読取専用・ツール使用禁止の日本語短報 |
| 自動診断の上限 | 同時1件、毎時3件、1件180秒。超過分はディスクに待機 |
| 監視自身の異常終了 | タスクスケジューラの毎分救済起動。既に稼働中ならIgnoreNewで無視。ログオン時にも起動 |

検出するのは正常/異常終了、PID不明・消失・再利用、状態/ログ欠損、未知status、既知の非ゼロ異常カウンタ、SUMO `Error:` とPython traceback。Warningの全件異常扱いはしない。研究のSHA・全人物会計・物理整合の完全検証は既存の独立検証器が担当し、この監視の正常表示をPASSに読み替えない。native buildはownerの状態・PIDと更新を監視し、compiler child全体の独立監査を代替しない。

最初の起動時に既存の終端履歴を基準登録し、過去の失敗を一斉再通知しない。その後の新しい終了・異常はイベント化する。状態ファイルの部分書込は3回連続で読めないときに通知する。run/attemptの同じパス・同じ異常種類は一度だけ保存し、再起動でも通知・AI処理を重複させない。研究runの再利用は禁止のまま。

イベントを永続化してからWindows通知と診断を実行する。Windows通知の`submitted`はAPIへの送信受付であり、ユーザーの閲覧確認ではない。診断の起動失敗・タイムアウト・中断は保全し、無制限な再試行をしない。診断結果はローカル受信箱で確認する。メール・Slack等への送信は行わない。

Windows通知はAI診断の同時実行・毎時上限と独立に進める。各tickで通知は最大1件とし、保留分を一度に処理して観測を長時間ふさがない。診断が実行中または毎時上限に達していても、次のtickで保留通知を処理する。通知API呼出しの処理時間もあるため、終了検知・通知の厳密な実時間保証はしない。2026-10-21修正の旧版・3件のRED/GREEN・30件の回帰試験と実反映確認は`verification/notification_queue_20261021/`へ保存する。イベントの原証跡と診断の毎時3件・180秒制限は維持する。

技術suite内の個別`purpose=fixture`の正常終了はイベント保存だけとし、通知・AIを起動しない（`not_required`）。suite全体の完了・個別fixtureの失敗/異常、研究coreやsmokeの完了は通知・診断の対象とする。多数の内部試験成功で診断キューを埋めないための運用上の区別であり、受入条件は変更しない。

## 導入・操作（リポジトリ直下）

このPCでは導入済み。二重起動せず、まず次で状態を確認する。

```powershell
.\04_プログラム\venv\Scripts\python.exe -B -X utf8 07_監視システム/watch.py status
```

`monitor_identity_matches=true`、プロセス`alive`、直近の観測時刻を合わせて確認する。Windowsタスク名は`JDRT-SimulationWatch`。venvのlauncher PIDと実際のPython PIDは異なる場合があるため、数値PIDだけで生存を判断しない。

ローカル受信箱は、上の出力`runtime`ディレクトリの`status.html`。10秒ごとに再読込し、観測が40秒超更新されなければ停止確認を促す。最後の観測に基づく表示であり、ブラウザ表示だけで現在の生存を証明しない。

```powershell
# 管理するのは監視タスクだけ。研究プロセスには作用しない。
Disable-ScheduledTask -TaskName JDRT-SimulationWatch
Stop-ScheduledTask -TaskName JDRT-SimulationWatch
# 再開前にwatch.py statusで旧監視プロセスの終了を確認する。
Enable-ScheduledTask -TaskName JDRT-SimulationWatch
Start-ScheduledTask -TaskName JDRT-SimulationWatch
# ログオン起動を含めて解除する場合（イベント原本は残す）
powershell.exe -NoProfile -ExecutionPolicy Bypass -File 07_監視システム/install.ps1 -Uninstall
```

別PCで新規導入するときは、現在使用するCodex実行ファイルの絶対パスで`configure.py --codex-exe <absolute-codex.exe>`を実行し、その後`install.ps1`を実行する。native buildも対象にする場合は`configure.py`へ`--native-root <absolute-native-root>`を追加する。`configure.py`は既存設定を上書きしない。移設時はタスクを停止して設定・対象を照合する。

`config.json`はこのPCの設定としてGit対象外。研究用設定からworkspaceを読み取り、choiceの`runs/*`・`smoke/*`・`technical/*`・`technical/*/execution`を自動発見する。登録済みnative rootの`build_state.json`と直下attemptの同名ファイルも対象。別系列や新しいnative rootは自動で範囲拡大せず、設定の`patterns`を更新して再起動する。再設定後は必ず対象とイベントを確認する。

作業データは`~/.jdrt-monitor/<workspace識別子>/`に置く。OneDriveの同期負荷とパッケージアプリのLocalAppData仮想化を避ける。`state.json`、`events/<id>.json`、診断の`.stdout.log`・`.stderr.log`・`.reply.txt`、`status.html`が保存される。監視の致命的例外種別は本フォルダのGit対象外`runtime/monitor_failures.jsonl`へ追記する。状態ファイルを削除して基準登録をやり直すと、未処理イベントの対応関係を失うため、勝手に削除しない。

診断要求モデルは運用正本に従い`gpt-6-luna / low`。起動指定・CLI応答と、サービス内部バックエンドの独立確認は区別する。モデル利用不可なら失敗保全し、別モデルへ自動変更しない。CLI更新で実行ファイルの位置・オプションが変わった場合は設定と人工probeを再確認する。

## 検証

```powershell
.\04_プログラム\venv\Scripts\python.exe -B -X utf8 -m unittest discover -s 07_監視システム -p test_watch.py
# 毎回新しい出力フォルダを指定。実際のCodex利用はこの人工probeだけでも発生する。
.\04_プログラム\venv\Scripts\python.exe -B -X utf8 07_監視システム/smoke.py --codex --output 07_監視システム/verification/<fresh-id>
```

実SUMO/研究coreは開始しない。`verification/`に導入時の失敗試行も保存する。PC電源断・スリープ・ログアウト中はローカル監視できない。外部からの死活監視や、このデスクトップchatへの自動投稿は今回の構成に含めない。セッションやCodexアプリを閉じても、Windowsにログインした状態でPCが稼働していれば監視は独立して継続する。

毎分の救済トリガーは監視プロセス不在時の起動用であり、毎分AIやシミュレーション検査を起動するものではない。常駐中はOSが重複起動を無視し、さらに監視本体のOS lockで二重writerを防ぐ。

実装の根拠：[Codex非対話実行](https://learn.chatgpt.com/docs/non-interactive-mode)、[Windowsの反復トリガー](https://learn.microsoft.com/en-us/powershell/module/scheduledtasks/new-scheduledtasktrigger?view=windowsserver2025-ps)。研究の開始・復旧・検証・正式記録は[joso-jdrt-runner](../.agents/skills/joso-jdrt-runner/SKILL.md)のゲートを維持する。
