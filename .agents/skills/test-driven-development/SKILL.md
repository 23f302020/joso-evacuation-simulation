# 契約に基づく変更と回帰防止

addyosmani/agent-skillsの研究向け適用版。[上流原文](references/upstream/skills/test-driven-development/source.md)は一般的なTDD技法の参照用。[スキル・エージェント運用](../../../05_タスク管理/スキル・エージェント運用.md)の権限・併用条件を適用する。

1. 現行仕様・PAP・Registryと既存試験から、変更が守る契約、対象、成功条件を特定する。利用中のtest runnerと対象試験commandを確認する。
2. 既存の失敗試験があれば再利用する。なければ不具合または未実装の契約を示す最小試験を作り、意図した理由で失敗することを確認する。収集失敗や依存不足だけをREDの証明にしない。
3. その契約を満たす最小変更を行い、対象試験が通ることを確認する。無関係な整理はしない。
4. 影響範囲に応じた回帰検証を行う。SUMO/TraCIの挙動は必要な実SUMO fixtureで確認し、mockだけで合格としない。

Pythonの試験設計には`python-testing-patterns`を併用する。native/build問題では既存のnative試験・build commandを使い、pytestへの移行を要求しない。

期待値は仕様・数式・人工入力から導き、観測した研究runの結果を正解として埋め込まない。PAPの除外規則・受入しきい値をGREENにするため変更しない。全件試験や上流の80/15/5比率を一律の採用条件にしない。

成果物は契約、RED/GREENのcommandと証跡、必要な回帰検証。この合格と研究セルの採用判定は分ける。
