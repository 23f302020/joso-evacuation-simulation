# 研究実装の差分レビュー

addyosmani/agent-skillsの研究向け適用版。[上流原文](references/upstream/skills/code-review-and-quality/source.md)は観点の参照用。[スキル・エージェント運用](../../../05_タスク管理/スキル・エージェント運用.md)に従い、通常は作業中のchat内でレビューする。

1. 今回の対象差分と既存dirty差分を区別し、変更理由・公開契約・参照元・入出力・必要な試験を把握する。
2. 正しさ、読みやすさと最小性、既存設計との整合、秘密情報や外部作用、実測に基づく性能の五観点で対象を確認する。隣接コードの整理や全面監査へ広げない。
3. 研究固有の見落としを確認する：人物会計、分母と時刻、情報分離、SHA/manifest、原本保全、観測と検証器の独立性、部分記録、旧証跡の流用、PAPと受入条件の不変性。
4. 指摘には具体的なfile/line、発生条件、実害、確認方法を付ける。一次成果物からの再計算が必要なら実際に行い、未実施ならその限界を記す。

全体のcode health向上を理由に研究ゲート違反を許容しない。別モデルの同意を独立検証の代用にしない。上流persona・モデル指定・自動commit・subagent起動は取り込まない。修正が必要な指摘は原因解析またはTDDへ戻す。

成果物は具体的な指摘と必要な検証、または指摘なしという結論と確認範囲・残る限界。レビュー終了からrun開始・record・公開の権限を推定しない。
