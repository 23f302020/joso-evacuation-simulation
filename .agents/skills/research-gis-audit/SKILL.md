# 地理空間入力の監査

①agency-agentsの[GIS QA](references/upstream/gis/gis-qa-engineer.md)と[Spatial Data Engineer](references/upstream/gis/gis-spatial-data-engineer.md)を研究向けに適用する。上流のPython例は雛形であり、実装済みvalidatorではない。[運用正本](../../../05_タスク管理/スキル・エージェント運用.md)を適用する。

1. 対象データの原本・版・SHA、形式、列/型、null/NoData、単位、範囲、対象時刻と、利用する道路/人口/施設の対応表を確認する。
2. 水平CRS、軸順、投影単位、座標変換をメタデータと実座標で照合する。標高は鉛直基準、地形/路面/橋面の区別と精度根拠を別に確認する。CRSが同じだけで標高基準一致や橋面高取得としない。
3. 形状の欠損・重複・自己交差、必要なnetwork接続、境界内外、点と施設/道路の対応を検査する。問題はfeature ID、座標、入力位置と件数で再現可能に示す。意図した切断・域外も含め仕様を確認し、全layerへ一律の無隙間規則を課さない。
4. 洪水時刻、実時間/モデル時間、補間、初期状態、閉鎖判定の対応を確認する。空間解像度・時刻間隔・元データ精度で観測できないものを明記する。
5. read→transform→writeの来歴と件数/対象領域の増減を照合する。必要な全件検証と制御点等の抜き取り確認を区別し、抜き取りで網羅性を保証しない。

成果物は検査対象・方法・一次証跡・適合/不適合/未確認と、入力への影響範囲。不明な基準・精度は未確認として残す。既存の検証済み証跡が同じ入力/変換SHAへ適用できれば再利用する。

原本・登録入力・凍結出力の修復、再投影、補間、欠測補完を監査と同時に自動実施しない。修正は別の許可範囲で新出力へ行い、研究入力化にはPAP/Registryと専用ゲートを適用する。
