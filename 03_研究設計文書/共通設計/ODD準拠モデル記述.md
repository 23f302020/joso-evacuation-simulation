## 1. Overview

### 1.1 Purpose and patterns

本モデルの目的は、河川氾濫時の道路閉鎖下で、住民の避難所到達可能性と車両交通を表現し、Scenario AとScenario BのType3/4避難完了率に方向性のある差を本モデルで検出できるかを確認することである。

再現対象は2015年常総市水害の全行動ではない。Phase 1実データ版は観測浸水8時点を利用するが、Phase 2・3の時間軸は加速浸水ストレスシナリオである。主に確認するパターンは、道路閉鎖の累積、避難所到達可否、停止・未到着、Type3/4完了率のrun間変動である。

### 1.2 Entities, state variables and scales

| 主体・環境 | 主な状態 |
|---|---|
| 人口メッシュ／出発地 | `origin_id`、人口、高齢者人口、緯度経度、SUMO edge |
| 避難者区分 | Type1〜4、車保有、高齢、バス候補、人数換算 |
| 自家用車 | 車両ID、出発地、避難所、route、出発時刻、到着・停止状態 |
| 救出走行 | Type3/4を送る車両、pickup、避難所、人数換算2.3人/台 |
| バス | 車両ID、定員、固定乗降地点、避難所、便、乗客、運行状態 |
| 道路 | SUMO edge、通行可否、最初の閉鎖時刻、速度、停止台数 |
| 浸水 | t0〜t7、浸水ポリゴン、道路閉鎖集合 |
| 避難所 | 洪水対応、安全判定、接続edge、受入目的地 |

空間は常総市を主対象とし、Phase 1では茨城県41市区町村へ手法移転デモを行う。Phase 3は6時間、SUMO内部1秒、評価出力は必要に応じて60秒間隔である。

### 1.3 Process overview and scheduling

1. 公開・公的データから道路、人口、浸水、行政区域、避難所を読み込む。
2. 人口メッシュと避難所を道路edgeへ接続する。
3. 浸水時系列から道路閉鎖時刻を生成する。
4. Phase 1では閉鎖道路を除外した最短経路と到達可否を求める。
5. Phase 2ではSUMO routeを生成し、TraCIで時刻別閉鎖、再経路探索、車両・渋滞ログを記録する。
6. Phase 3ではType1〜4、救出走行、バス候補、Scenario A/B routeを生成する。
7. 各seedで車両を進行させ、閉鎖、再経路探索、乗降、到着、運行打切りを処理する。
8. 終了時に車両・人員会計を検査し、正本ゲートに合格したrunだけを評価へ接続する。
9. A側3run、B側5runを集計し、Type3/4完了率の正式判定と補助・診断指標を分離して出力する。

## 2. Design concepts

| 概念 | 本モデルでの扱い |
|---|---|
| Basic principles | 道路ネットワーク最短経路、SUMO微視的交通流、TraCI動的制御、人数・車両会計 |
| Emergence | 渋滞、待ち行列、未到着、run間の初期条件感応性は個別車両相互作用から生じる |
| Adaptation | 車両は閉鎖時に再経路探索する。バスは固定された乗降地点・避難所間を往復する |
| Objectives | 車両は指定避難所への到達、バスは候補者輸送を行う。全体最適化は行わない |
| Learning | エージェントの学習はない |
| Prediction | 将来の浸水や混雑を予測して行動する機構はない |
| Sensing | TraCIから道路閉鎖、車両状態、バス位置、予約候補・乗客状態を取得する |
| Interaction | 同一道路上の車両相互作用、閉鎖道路、乗降、救出走行削減を通じて相互作用する |
| Stochasticity | SUMO seedにより車両挙動が変化する。A3/B5の複数runで観測する |
| Collectives | Type3/4、出発地、バス便、Scenario A/B単位で集計する |
| Observation | 完了率、到着・未到着、完了時間、輸送人数、渋滞、会計、manifestを記録する |

## 3. Details

### 3.1 Initialization

- 人口・高齢者人口は250mメッシュから設定する。
- Scenario Aは自家用車8,164台＋救出走行1,405台、計9,569台である。
- Scenario Bは自家用車8,164台＋救出走行1,351台、計9,515台にバスを加える。
- Type3/4正式評価分母は3,231.5人で固定する。
- A側seedは23423、42、1、B側seedは23423、42、1、7、101である。
- Phase 3は`time-to-teleport=-1`とする。

### 3.2 Input data

| 入力 | 用途 |
|---|---|
| GSI浸水KML・A31a | 浸水範囲と道路閉鎖条件 |
| N03行政区域 | 市区町村抽出・クリップ |
| OSM道路 | 経路探索・SUMO道路網 |
| P20避難施設 | 避難所候補・洪水対応施設 |
| e-Stat 250m人口 | 出発地人口・高齢者人口 |
| 車両保有統計 | 車両数・車非保有世帯推計 |
| 派生CSV/JSON/XML | edge対応、出発地、避難所、閉鎖時系列、route、run設定 |

### 3.3 Submodels

1. **浸水道路閉鎖**：浸水深0.5m以上相当を閉鎖条件とし、時刻別edge集合へ変換する。
2. **避難所選択**：安全な避難所候補へ道路距離に基づいて割り当てる。
3. **車両発生**：人口・保有統計から自家用車・救出走行を生成する。
4. **Type分類**：車保有と高齢条件からType1〜4を付与する。
5. **救出走行会計**：Type3/4を2.3人/台で人数換算する。
6. **バス運行**：事前固定した乗降地点・避難所間をTraCI状態機械で往復し、定員内で乗降する。需要に応じた経路最適化はしない。
7. **閉鎖時再経路探索**：閉鎖edgeを避けるよう車両routeを更新し、成立しない場合を記録する。
8. **終了・会計**：到着、未到着、乗車中未到着、残queue、車両総数の保存則を検査する。
9. **正式評価**：Type3/4完了率のみを方向判定に用い、完了時間、公平性、渋滞を補助・診断へ分離する。

### 3.4 Evaluation and fitness for purpose

本モデルは、常総市の加速浸水ストレス条件下でA/B比較基盤を構築し、設定したType3/4完了率差を検出できるかを調べる目的には適合する。実際の住民の警報認知、出発時刻分布、避難所選択、予約型DRT、実運行制約、浸水深・流速による連続的速度低下は再現していないため、実災害の人数予測や動的DRT最適化には適用しない。
