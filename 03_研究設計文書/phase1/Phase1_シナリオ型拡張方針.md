# Phase 1 シナリオ型拡張方針

作成日：2026/05/01
最終更新：2026/05/05（シナリオ生成ルール最終版）

---

## 1. 目的

本書は、Phase 1 の現状システムを受けて、浸水時系列データをそのまま再現する構成から、研究成果として説明しやすい「シナリオ型浸水拡大・任意地点ルート検索」へ拡張する判断を整理するための文書である。

本版では、P1-S1〜P1-S5で採用済みのシナリオ生成ルールを最終版として整理し、卒論および今後の実装説明で使用する表現を明確にする。

---

## 2. 現状の課題

Phase 1 では、実データを用いて浸水時刻ごとの道路閉鎖と迂回ルート検索を実装している。

一方で、現状の浸水時系列データでは、時間ごとの浸水範囲の変化が小さい、またはルート検索の出発地点として扱われる人口メッシュが限られているため、可視化上は「避難ルート検索の成果」が少なく見える。

特に、地図上では広い浸水範囲が表示されている一方、ルート検索では浸水エリアと照合された一部の人口メッシュ重心のみが出発地点になっている。そのため、浸水マップ全体の広がりに対して、検索される避難ルート数が少ないという構造的な差がある。

## 4. 研究上の判断

| 判断項目 | 採用方針 | 理由 |
| --- | --- | --- |
| 実データの扱い | 対象地域・浸水範囲・避難所・道路ネットワークの根拠として継続利用する | 完全な仮想条件にせず、2015年常総市の事例に基づく研究として説明できるため |
| 浸水推移 | 最終浸水範囲を t0〜t7 に段階分割する | 現状の実時系列では変動が小さく、ルート変化の可視化効果が弱いため |
| 破堤地点 | 常総市三坂町の破堤地点（BP030近傍）を基準点として採用する | 2015年9月10日12時50分の破堤時刻・地点が既存文書に整理済みであるため |
| ルート検索 | 任意地点から到達可能な最寄り避難所へのルート検索を追加する | 浸水地域内の特定地点を想定した避難行動を確認でき、道路閉鎖後に到達不能な避難所を避けられるため |
| 道路閉鎖 | 浸水深0.5m以上を閉鎖条件とする方針を維持する | 既存 Phase 1 の閉鎖条件と整合するため |
| 累積閉鎖 | シナリオ版では累積閉鎖を採用する | 洪水時に一度冠水した道路を安全側に扱い、浸水進行に伴う避難困難化を表現するため |

## 8. Phase 1 シナリオ生成ルール（最終版）

Phase 1 シナリオ版では、2015年鬼怒川氾濫を対象地域・データ根拠としつつ、実際の浸水時系列を完全再現するのではなく、最終浸水範囲を段階的に拡大する検証用シナリオとして扱う。

### 8-1. 最終確定ルール

| 決定事項 | 最終ルール |
| --- | --- |
| シナリオの位置づけ | 実データを根拠にした避難ルート探索機能の検証シナリオ |
| 最大浸水範囲 | A31a 国管理河川（`08_10`）の `waterDepth >= 2`（浸水深0.5m以上） |
| 対象地域 | N03 行政区域（2015年版）で常総市（`N03_007 == "08211"`）に限定 |
| 最大浸水ポリゴン数 | 290ポリゴン |
| 拡大基準点 | BP030近傍の破堤点（緯度36.0885、経度139.9633） |
| 破堤時刻 | 2015年9月10日 12時50分 |
| 距離指標 | A31a各ポリゴン重心から破堤点までのユークリッド距離 |
| 距離計算CRS | EPSG:6690 |
| 時間配分 | 破堤時刻から各シナリオ時点までの経過時間 ÷ 総経過時間141.5時間 |
| 拡大方法 | 進行率を距離分位点として用い、破堤点に近いポリゴンから順に採用 |
| 累積方式 | 各時点では、その時点の距離分位点以内にある全ポリゴンを採用する |
| 道路閉鎖条件 | シナリオ浸水範囲と道路リンクが交差した場合に閉鎖対象とする |
| ルート検索 | 任意地点から到達可能な最寄り洪水対応避難所への最短経路を探索する |
| 避難所データ | P20避難施設データから抽出した常総市の洪水対応避難所19件 |
| 出力成果物 | `04_プログラム/output/scenario_v2/scenario_route_simulation.html`、`scenario_v2_summary.csv` |

### 8-2. 時点別進行率

t0〜t7は実測浸水推移そのものではなく、既存の8時点の時刻枠に、最終浸水範囲の距離分位点を割り当てたシナリオ時点である。

| t1 | 2015-09-11 06:00 | 12.2% | 36 | 12 |
| t2 | 2015-09-11 18:00 | 20.6% | 60 | 15 |

### 8-3. 最終ルールの説明文

Phase 1シナリオ版では、A31a浸水想定区域のうち常総市内かつ浸水深0.5m以上の範囲を最大浸水範囲とし、破堤地点から各浸水ポリゴン重心までの距離順に、破堤後の経過時間比率に応じて t0〜t7 へ累積的に拡大する。各時点の浸水範囲と道路リンクを重ね合わせ、浸水範囲と交差する道路を閉鎖し、任意地点から到達可能な最寄り洪水対応避難所への避難経路を探索する。

## 9. 採用根拠と不採用案（2026/05/02）

Step 1 再検証（i1 閉鎖時系列の原因調査）の結果を踏まえ、以下の案を確定した。

### P1-S1（最終浸水範囲）：A31a waterDepth≥2 × N03 常総市クリップ

| 項目 | 内容 |
| --- | --- |
| **採用データ** | A31a 国管理河川（08_10）、waterDepth コード値 ≥ 2（浸水深 0.5m 以上） |
| **地域絞り込み** | N03 行政区域（2015年版）で常総市（N03_007 == "08211"）のポリゴン内に限定 |
| **採用理由** | flood_polygons.pkl の一部時点はフォールバック（茨城県全域 8792 件）を含み、地図表示・距離計算が不正確になるため、A31a GML から直接ロードして常総市範囲に限定する |

**不採用案と理由：**
- `flood_polygons.pkl` の最大ポリゴン数時点を流用 → フォールバック（全茨城県）が選ばれ、地図上の浸水表示が茨城県全域に広がる
- KML 8時点の union → 深度属性がなく、0.5m 以上の閉鎖条件との整合が取れない

### P1-S2（段階的浸水拡大ルール）：破堤点からの距離 × 経過時間比例進行率

| 項目 | 内容 |
| --- | --- |
| **基準点** | BP030 近傍破堤点（lat: 36.0885, lon: 139.9633）|
| **距離指標** | A31a 各ポリゴン重心から基準点までのユークリッド距離（EPSG:6690 投影 CRS） |
| **進行率** | 破堤（12:50）からの経過時間 ÷ 総経過時間（141.5h）で各時点の距離分位点を決定 |
| **進行率の値** | t0=3.7%, t1=12.2%, t2=20.6%, t3=29.1%, t4=37.6%, t5=46.1%, t6=54.6%, t7=100% |
| **累積方式** | 各時点では「その分位点以内の全ポリゴン」を採用（累積封鎖と整合） |

**不採用案と理由：**
- 旧 SCENARIO_PROGRESS=[0.0002, ..., 0.03, 1.0] → t6=3% → t7=100% の急変が非現実的
- 面積割合分割 → 道路閉鎖数との対応が取りにくく、時刻の解釈が難しい

## 10. 最終結論

Phase 1 は、実データのみの再現に限定するとルート検索結果の変化が小さく、成果として見えにくい。

そのため、実データを基礎資料として維持しながら、最終浸水範囲を段階的に広げるシナリオ型の浸水推移を追加し、任意地点から近くの避難場所へのルート検索を行える構成を Phase 1 の最終方針として採用する。

この変更は、実災害の完全再現ではなく、浸水進行に応じた避難ルート探索の有効性を示すためのシミュレーションとして位置づける。

## 11. 茨城県内拡張に向けた追加方針

常総市以外にも茨城県内には洪水浸水想定区域が存在するため、今後の拡張では対象地域を常総市固定ではなく、茨城県内の市町村または浸水想定区域から選択できる構造にする。

### 11-1. 修正前と修正後

| 項目 | 修正前 | 修正後 |
| --- | --- | --- |
| 対象地域 | 常総市・鬼怒川周辺 | 茨城県内の対象市町村または対象浸水区域 |
| 浸水想定区域 | A31a `08_10` と鬼怒川関連データが中心 | A31a `08_10` に加え、その他河川 `08_20` を使用 |
| 行政区域 | `JOSO_CODE = 08211` による固定抽出 | N03 行政区域を用いて市町村単位で抽出 |
| 道路ネットワーク | 常総市道路ネットワークのみ | 対象市町村単位で道路ネットワークを取得 |
| 避難所 | 常総市の洪水対応避難所19件 | 対象市町村および近傍の洪水対応避難所 |
| 人口メッシュ | 常総市周辺の固定メッシュ | 浸水想定区域または行政区域と交差するメッシュ |

### 11-2. 追加データ取得方針

| データ | 状態 | パス | 備考 |
| --- | --- | --- | --- |
| A31a 茨城県 その他河川（`08_20`） | ✅ 取得済み | `data/flood_hazard_a31/A31a-24_08_20_GML/` | `20_浸水想定区域`（Polygon・使用対象）と `30_設計洪水位`（Line・不要）の2サブフォルダを含む |
| N03 茨城県 行政区域 | ✅ 取得済み | `data/admin_boundary/N03-150101_08_GML/` | 2015年1月1日版・茨城県全市区町村 |
| P20 茨城県 避難施設 | ✅ 取得済み | `data/shelters/避難施設データ_茨城/P20-12_08` | 茨城県全域 2,326件（市区町村コードで絞り込む） |
| T001178 250mメッシュ人口 | ✅ 取得済み | `data/population_mesh/.../tblT001178Q08.txt` | `Q08` = 茨城県全域対応済み |
| 道路ネットワーク | コード修正後に取得 | ─ | osmnxで対象市町村ごとに動的取得（静的ファイル不要） |

> **実装時の注意:** 人口メッシュは現在 `KEY_CODE[:6] in ("543907", "543917")` で常総市に固定されている。
> 他市町村へ拡張する際は、N03 境界ポリゴンとの空間交差でメッシュを抽出する方式に変更すること（プレフィックスハードコードを廃止）。

### 11-3. 実装前の判断

県全域を一括で処理すると道路ネットワークとHTML出力が重くなる可能性がある。
そのため、最初は茨城県内の対象市町村を選択し、その範囲内で浸水シナリオと避難ルート検索を行える構成にする。
