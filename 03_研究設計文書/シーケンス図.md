## 1. STEP 1a — c3_get_road_network.py（道路NW取得）

```mermaid
sequenceDiagram
    actor 研究者
    participant C3 as c3_get_road_network.py
    participant CFG as config.py
    participant OSM as OpenStreetMap API
    participant FS as ファイルシステム

    研究者->>C3: python c3_get_road_network.py
    C3->>CFG: import（BBOX_NORTH/SOUTH/EAST/WEST, GRAPHML_PATH, EDGES_GPKG_PATH, NETWORK_MAP_PATH）
    CFG-->>C3: 定数返却

    C3->>OSM: ox.graph_from_bbox(bbox, network_type='drive')
    OSM-->>C3: MultiDiGraph（ノード・エッジ）

    C3->>C3: ox.graph_to_gdfs(G) → nodes_gdf, edges_gdf
    C3->>C3: edges_gdf.to_crs('EPSG:6668')

    C3->>FS: ox.save_graphml(G, GRAPHML_PATH)
    FS-->>C3: joso_road_network.graphml 保存完了

    C3->>FS: edges_gdf.to_file(EDGES_GPKG_PATH, driver='GPKG')
    FS-->>C3: joso_edges.gpkg 保存完了

    C3->>C3: folium.Map() + GeoJson(edges_gdf.to_crs('EPSG:4326'))
    C3->>FS: map.save(NETWORK_MAP_PATH)
    FS-->>C3: joso_network_map.html 保存完了

    C3-->>研究者: 完了メッセージ（エッジ数・ノード数）
```

## 2. STEP 1b — e1_load_flood_data.py（浸水データ読み込み）

```mermaid
sequenceDiagram
    actor 研究者
    participant E1 as e1_load_flood_data.py
    participant CFG as config.py
    participant KML as flood_kml/*.kml（8ファイル）
    participant GML as A31a-24_08_10_GML/*.gml（84ファイル）
    participant FS as ファイルシステム

    研究者->>E1: python e1_load_flood_data.py
    E1->>CFG: import（FLOOD_KML_DIR, A31a_GML_DIR, FLOOD_PKL_PATH, FLOOD_MAP_PATH, KINUGAWA_RIVER_NUMBER）
    CFG-->>E1: 定数返却

    loop 8時点分（t0〜t7）
        E1->>KML: gpd.read_file(kml_path, driver='KML')
        KML-->>E1: GeoDataFrame（LineString, EPSG:4326）
        E1->>E1: .to_crs('EPSG:6668')
        E1->>E1: .buffer(50m) → PolygonGDF
    end

    E1->>GML: pyogrio.list_layers(gml_path)
    GML-->>E1: レイヤー名一覧

    loop 84ファイル分
        E1->>GML: gpd.read_file(gml_path, layer='...')
        GML-->>E1: GeoDataFrame（Polygon, EPSG:6668）
    end

    E1->>E1: concat → 全Polygon GDF
    E1->>E1: .query("riverNumber == KINUGAWA_RIVER_NUMBER and waterDepth >= 2")
    Note over E1: waterDepth>=2 = 浸水深0.5m以上（閉鎖しきい値）

    E1->>E1: KML時刻別バッファ × A31a深度ポリゴン → 統合辞書 {timestamp: GeoDataFrame}

    E1->>FS: pickle.dump(flood_polygons, FLOOD_PKL_PATH)
    FS-->>E1: flood_polygons.pkl 保存完了

    E1->>E1: folium.Map() + 時刻別PolyGdf可視化
    E1->>FS: map.save(FLOOD_MAP_PATH)
    FS-->>E1: flood_timeline_map.html 保存完了

    E1-->>研究者: 完了メッセージ（8時点・ポリゴン数）
```

## 3. STEP 2 — i1_spatial_join.py（浸水×道路 空間照合）

```mermaid
sequenceDiagram

    CFG-->>I1: 定数返却

    I1->>FS: gpd.read_file(EDGES_GPKG_PATH)
    FS-->>I1: edges_gdf（EPSG:6668）

    I1->>FS: pickle.load(FLOOD_PKL_PATH)
    FS-->>I1: flood_polygons（dict[str, GeoDataFrame]）

        I1->>I1: closure_dict[timestamp] = [edge_id, ...]
    end

    I1->>FS: pickle.dump(closure_dict, CLOSURE_PKL_PATH)
    FS-->>I1: closure_dict.pkl 保存完了
```

## 5. STEP 4 — i3_route_search.py（迂回ルート検索）

```mermaid
sequenceDiagram
    actor 研究者
    participant I3 as i3_route_search.py
    participant CFG as config.py
    participant FS as ファイルシステム

    研究者->>I3: python i3_route_search.py
    I3->>CFG: import（GRAPHML_PATH, CLOSURE_JSON_PATH, MESH_CSV_PATH, SHELTER_SHP_PATH, ORIGINS_CSV_PATH, SHELTERS_CSV_PATH, UNREACHABLE_PATH, ROUTES_DIR）
    CFG-->>I3: 定数返却

    note over I3: === 入力データ読み込み ===

    I3->>FS: ox.load_graphml(GRAPHML_PATH)
    FS-->>I3: G（networkx MultiDiGraph）

    I3->>FS: json.load(CLOSURE_JSON_PATH)
    FS-->>I3: closure_dict（dict[str, list[str]]）

    I3->>FS: pd.read_csv(MESH_CSV_PATH, encoding='shift_jis', header=None, dtype=str)
    FS-->>I3: mesh_df（63列）

    I3->>FS: gpd.read_file(SHELTER_SHP_PATH)
    FS-->>I3: shelter_gdf（EPSG:4612 → to_crs('EPSG:6668')）

    note over I3: === 出発地・避難所 CSV生成 ===

    I3->>I3: 250mメッシュ重心計算（JGD2011投影）→ origin_points（座標・人口）
    I3->>FS: origin_df.to_csv(ORIGINS_CSV_PATH, index=False)
    FS-->>I3: origin_points.csv 保存完了

    I3->>I3: shelter_gdf[洪水対応 & 常総市] → 19件フィルタ
    I3->>FS: shelter_df.to_csv(SHELTERS_CSV_PATH, index=False)
    FS-->>I3: shelters.csv 保存完了

    note over I3: === 時点別ルート検索 ===

    loop 8時点分（t0〜t7）
        I3->>I3: G_sub = G.copy()
        I3->>I3: G_sub.remove_edges_from(closure_dict[timestamp])
        loop 各出発地
            I3->>I3: ox.nearest_nodes(G_sub, origin_lon, origin_lat)
            loop 各避難所
                I3->>I3: nx.shortest_path(G_sub, orig_node, dest_node, weight='length')
                alt 経路あり
                    I3->>I3: ルートリストに追加
                else 経路なし（NetworkXNoPath）
                    I3->>I3: unreachable_list に追加
                end
            end
        end

        I3->>I3: folium.Map() + 経路PolyLine描画
        I3->>FS: map.save(ROUTES_DIR/evacuation_routes_t{n}.html)
        FS-->>I3: HTML 保存完了
    end

    note over I3: === 逃げ遅れ記録 ===

    I3->>FS: unreachable_df.to_csv(UNREACHABLE_PATH, index=False)
    FS-->>I3: unreachable_agents.csv 保存完了（実データ版の到達不可集計）

    I3-->>研究者: 完了メッセージ（逃げ遅れ人数・時点別内訳）
```

## 7. Phase 1 シナリオ型任意地点ルート検索（最終版）

シナリオ型拡張では、`v2_scenario_route_simulation.py` がA31a最終浸水範囲を t0〜t7 に段階配分し、道路閉鎖・避難所・道路グラフをHTMLへ埋め込む。利用者は生成済みの `scenario_route_simulation.html` 上で時刻を選び、地図上の任意地点をクリックして、その時点の浸水・道路閉鎖を考慮した避難ルートを確認する。

| 項目 | 修正前 | 修正後 |
| --- | --- | --- |
| 画面操作 | t0〜t7 の HTML ファイルを個別に開く | トップページまたはシナリオ画面から時刻を選択する |
| 出発地点 | 人口メッシュ重心をプログラム側で固定 | ユーザーが地図上で任意地点をクリックする |
| 浸水確認 | 各 HTML の浸水レイヤーを目視確認 | 選択時刻のシナリオ浸水範囲を表示する |
| 道路閉鎖 | 実データ版の閉鎖タイムラインを利用 | シナリオ浸水範囲から生成した閉鎖エッジを時刻別に利用する |
| ルート確認 | 事前生成されたルートを確認 | 指定地点から到達可能な最寄り洪水対応避難所へのルートを確認する |

```mermaid
    V2->>A31: waterDepth>=2 の浸水想定区域を読み込み
    A31-->>V2: A31a浸水ポリゴン

    N03-->>V2: 常総市ポリゴン
```

### 7-2. 画面操作シーケンス

```mermaid
sequenceDiagram
    actor 利用者
    participant UI as シナリオ版HTML
    participant Flood as シナリオ浸水レイヤー
    participant Route as ルート検索処理
    participant Shelter as 洪水対応避難所19件
    participant Map as 地図表示

    利用者->>UI: 時刻 t0〜t7 を選択
    UI->>Flood: 選択時刻の浸水範囲を取得
    Flood-->>Map: 浸水レイヤーを表示

    利用者->>Map: 出発地点をクリック
    Map->>Route: 出発地点座標と選択時刻を渡す
    Route->>Route: 選択時刻の閉鎖道路を除外
    Route->>Shelter: 候補避難所を取得
    Shelter-->>Route: 洪水対応避難所一覧
    Route->>Route: 到達可能な最寄り避難所を探索
    Route-->>Map: 避難ルートと避難所を返す
    Map-->>利用者: 浸水範囲・閉鎖考慮ルート・避難所を表示
```

この流れにより、常総市シナリオ版は「時刻別の静的確認」だけでなく、「任意地点を想定した避難ルート確認」として説明できる。

## 8. Phase 1 茨城県内拡張・統合版生成（最終成果物）

茨城県内拡張版では、`city_scenario.py` が40市区町村の個別HTMLを生成し、`gen_unified.py` が県全体の統合シミュレーションを生成する。`gen_index.py` は、統合版、市区町村別版、常総市参考版、対象外4市町村をまとめたトップページを生成する。

```mermaid
sequenceDiagram
    actor 研究者
    participant City as city_scenario.py
    participant A31 as A31a 08_10/08_20
    participant N03 as N03行政区域
    participant Shelter as GSI洪水対応避難所
    participant Road as 市区町村別道路NW
    participant Unified as gen_unified.py
    participant Index as gen_index.py
    participant FS as output/

    loop シナリオ生成対象40市区町村
        研究者->>City: python city_scenario.py --code {code}
        City->>N03: 市区町村境界を取得
        City->>A31: 境界内の浸水想定区域を抽出
        City->>Road: 道路ネットワークを読み込み
        City->>Shelter: 洪水対応避難所を抽出
        City->>City: 浸水想定区域と道路リンクを照合
        City->>FS: scenario_cities/{code}/scenario_route_simulation.html 保存
    end

    研究者->>Unified: python gen_unified.py
    Unified->>FS: scenario_cities/{code}/assets/data.js を集約
    Unified->>FS: prefecture_layers/t0.js〜t7.js を参照
    Unified->>FS: unified/scenario_route_simulation.html 保存

    研究者->>Index: python gen_index.py
    Index->>FS: 市区町村リンク40件と対象外4件を登録
    Index->>FS: index.html 保存
    Index-->>研究者: Phase 1確認トップページ生成完了
```
