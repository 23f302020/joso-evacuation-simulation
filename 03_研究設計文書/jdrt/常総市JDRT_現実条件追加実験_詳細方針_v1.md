# 常総市JDRT 現実条件追加実験 詳細方針 v1

> 方針固定日：2026-09-11  
> 対象：常総市（08211）  
> 状態：実験構造・実施順・検証原則を固定。v2中核20/20完了。R0先行実装・完了1セルは正式採用保留。実測根拠が必要な数値・新PAPは未確定。  
> ユーザー判断：現在の20回を完了した後、バスなしを含む現実条件版を独立実験として進める

> 2026-10-15再開時の更新：対象はユーザー選択の「現在の運用＋2015年型洪水」。仮定を明示した設計と不足資料収集を並行する。具体的な新値と時計の採否は[仮定シナリオ設計案](常総市JDRT_現実条件版_仮定シナリオ設計案_v1.md)を参照。既存閉鎖の数日→モデル6時間圧縮を確認したため、本書の6時間・15分を実時間の政策効果と解釈しない。正式新PAP・Registry・入力固定前の後続runは禁止のまま。

> 最新の時間軸判断：2026-10-15、ユーザーは実時間洪水入力再構築先行を選択。圧縮時計を使う第一案は不採用。[再構築方針・取得監査](../../02_情報調査/氾濫・浸水/jdrt_realtime_20261015/実時間洪水入力_再構築方針・取得監査.md)に従い、数値水深格子取得・初期状態/評価窓/道路対応の検証後に新PAPへ固定する。

## 1. 方針の結論

現行JDRT v2は、4種類の配車方法を同じ条件で比較する**統制実験**として、設定を変更せず20回を完了する。

その後、現実の避難行動を基準にした別系列の実験を作り、次の2点を分けて調べる。

1. 予約型避難車両を導入することで、現在の避難行動から何が変わるか。
2. 予約型避難車両を導入したうえで、15分遅れの道路閉鎖予測を配車に使うことで何が変わるか。

新実験は既存Phase 1〜3、Scenario C、JDRT v1/v2の設定・出力へ混ぜない。正式なprotocol名、Parameter Registry、入力SHA、出力先を新しく分離する。

---

## 2. 現行JDRT v2との関係

| 項目 | 現行JDRT v2 | 現実条件追加実験 |
|---|---|---|
| 主な目的 | 4種類の配車方法を比較する | バス導入効果と予測情報の効果を分けて比較する |
| バスなし条件 | なし | あり |
| JDRT利用率 | Type3/4の100%を上限需要として設定 | 根拠に基づく標準値を設定し、感度も確認する |
| 予約時刻 | 全件0秒 | 現実的な時間分布を設定する |
| 比較単位 | 同一seedの4方式 | 同一人物・同一seedの3条件 |
| 位置づけ | 統制実験 | 現実性を高めた追加実験 |

現行v2の20回を途中で変更しない。現実条件の入力やコードをv2へ遡及適用せず、v2の完了・評価後に新系列へ進む。

## 3. 研究質問

### RQ-A：導入効果

> 現在の避難行動に予約型避難車両を追加した場合、高齢かつ車を持たない住民の6時間以内避難完了率、待ち時間、立ち往生、道路混雑はどのように変わるか。

### RQ-B：予測情報の効果

> 同じ予約型避難車両を運用する場合、道路閉鎖予測を使わない配車と、実際より15分遅れた閉鎖予測を使う配車で、避難完了率、待ち時間、立ち往生、道路混雑はどのように変わるか。

RQ-AとRQ-Bを混ぜない。「バスを導入した効果」と「予測を使った効果」を別の差として算出する。

## 4. 中核の3条件

| 条件ID（仮称） | 非専門家向け名称 | JDRT | 配車方法 | 閉鎖予測 | 比較上の役割 |
|---|---|---:|---|---|---|
| REAL-R0 | 現在の避難行動 | なし | なし | なし | バス導入前の基準 |
| REAL-R1 | 現在の避難行動＋予約型避難車両 | あり | 待ち時間・支援必要度を使用 | 使わない | バス導入効果の比較先 |
| REAL-R2 | 現在の避難行動＋予約型避難車両＋閉鎖予測 | あり | R1と同じ情報＋閉鎖緊急度 | 実際より15分遅れ | 不完全な予測情報の効果を確認 |

中核実験は3条件×paired 5seedの**15セル**とする。seedは現行と同じ`23423`、`42`、`1`、`7`、`101`を第一候補とし、正式PAPで固定する。

### 許可する差

- R0対R1：JDRTの有無と、JDRT利用者の交通手段割当だけを変える。
- R1対R2：配車担当へ渡す道路閉鎖予測情報だけを変える。

### 変えてはいけないもの

同一seed内では、人口、個人属性、出発地、避難先、実際の道路閉鎖、背景交通の実現値、比較に関係しない車両挙動を共通にする。

## 5. 「現在の避難行動」の定義

バスなしを「全員がその場に残る」と自動設定しない。車を持たない人について、少なくとも次の交通手段を人物単位で区別する。

| 交通手段 | 内容 | 必要な設定 |
|---|---|---|
| 自家用車 | 本人・同一世帯の車で避難 | 車保有、乗員、出発時刻 |
| 家族・近隣送迎 | 別世帯等の車へ同乗 | 送迎可能割合、追加走行、乗員重複防止 |
| 徒歩 | 徒歩で避難 | 歩行可否、速度、距離上限、浸水通行規則 |
| 従来型の救援 | 行政・地域等の車両が迎えに行く | 車両数、定員、運行規則、実在根拠 |
| 移動手段なし | 制限時刻まで出発できない | 終了理由と人数の保存 |
| JDRT | R1/R2で予約型車両を利用 | 利用率、予約時刻、乗降、配車規則 |

各人物は各条件で主要交通手段を1つだけ持つ。R1/R2でJDRTへ移る人物については、R0で何をしていた人物かを対応表に残す。

```text
同じ人物
  R0：徒歩／家族送迎／従来救援／移動手段なし
  R1：JDRTへ転換、またはR0の交通手段を維持
  R2：R1と同じ交通手段。JDRTの配車判断だけ変更
```

これにより、JDRT利用者を徒歩・送迎・救援車でも同時に輸送する二重計上を防ぐ。

## 6. 実験前に確定する設定

### 6.1 必須設定

| 分類 | 確定する内容 | 現行値・状態 | 現実条件版での扱い |
|---|---|---|---|
| 現在行動 | 車を持たない人の交通手段割合 | JDRT v2にはバスなし条件なし | 根拠を調査し、人物台帳として固定 |
| JDRT利用 | 対象者と利用率 | Type3/4 3,255人が100%利用 | 標準値を根拠付きで固定。100%は上限感度へ移す |
| 予約 | 予約発生時刻 | 1,440件が全て0秒 | 避難情報後の時間分布として固定 |
| 自家用車 | 出発時刻と乗員 | 8,164台 | 現在行動と整合する台数・時刻・乗員を固定 |
| 背景交通 | 通常交通、送迎車、緊急車両 | 避難用自家用車が中心 | 含める範囲を明示し、二重生成を防止 |
| JDRT車両 | 台数、車種、定員 | 一般4台×8人、福祉1台×4人 | 実際に確保可能な台数・定員を根拠付きで固定 |
| 待機場所 | 車庫・営業所等の初期位置 | 既存pickup edge | 現実の出発拠点と道路接続を確認 |
| 乗降 | 利用者別の乗車・降車時間 | 全予約で各300秒 | 一般・移動支援必要者を分けるか決定 |
| 運行 | 相乗り、再割当、キャンセル | 相乗りなし、再割当なし | 実運用規則を確認。変更時はR1/R2共通 |
| 避難所 | 開設時刻、収容人数、福祉対応 | 安全確認済み9施設、容量無制約 | 不明値と0人を区別し、満員時の代替先を固定 |
| 浸水・閉鎖 | 実際の閉鎖、予測誤差 | 8時点、R2は15分遅れ | True Worldと配車用予測を分離して維持 |
| 終了条件 | 評価時刻 | 21,600秒 | 原則維持。変更する場合は全条件共通 |

### 6.2 根拠の優先順位

設定値は次の順で採用する。

1. 常総市・交通事業者・国や県の公表資料
2. 2015年災害記録、地域防災計画、避難行動調査
3. 対象地域に近い公的統計・査読研究
4. 既存データからの再現可能な算出
5. 根拠が得られない場合の明示的なシナリオ仮定

仮定値を実態値とは呼ばない。各値に「実測・公表」「派生」「仮定」の区分と確信度を付ける。

### 6.3 数値確定ゲート

次が揃うまで、新系列の実装とfull runを開始しない。

- 現在行動の交通手段割合
- JDRT標準利用率と予約時刻分布
- 標準fleet・定員・待機場所
- 乗降時間
- 避難所の容量・開設・代替規則
- 背景交通の範囲
- 中核と感度の全条件一覧
- 主指標、除外規則、停止規則

## 7. 人物・車両・予約の対応規則

比較可能性を保つため、seedごとに次の台帳を先に生成する。

| 台帳 | 主な列 | 目的 |
|---|---|---|
| 人物台帳 | person_id、Type、支援必要度、origin、shelter | 全人口と属性を固定 |
| 条件別交通手段台帳 | person_id、R0/R1/R2の交通手段、転換理由 | 二重輸送と未割当を防ぐ |
| 車両乗員台帳 | vehicle_id、person_id、出発時刻 | 乗員数と車両数を対応付ける |
| JDRT予約台帳 | request_id、person_id群、予約時刻、乗車地、避難先 | 予約人数・時刻・行先を固定 |
| 車両台帳 | vehicle_id、車種、定員、初期位置、利用可能時刻 | fleetを再現可能にする |

必須保存則は次のとおりとする。

```text
全人口 = 各交通手段へ割り当てた人物 + 明示的な非避難者
各人物の主要交通手段数 = 1
JDRT予約の人物合計 = JDRTへ割り当てた人物
車両ごとの乗員数 <= 定員
避難完了 + 立ち往生 + 未出発 + その他の理由付き終端 = 対象人口
```

## 8. 評価指標

### 8.1 主指標

現行JDRTとの連続性を保ち、Type4（高齢かつ車を持たない住民）の21,600秒までの避難完了率を第一候補とする。正式な分母と条件横断の人物定義は新PAPで固定する。

### 8.2 必須の比較値

| 比較 | 算出する差 | 意味 |
|---|---|---|
| R1 − R0 | 同一seedのバスあり－バスなし | JDRT導入による変化 |
| R2 − R1 | 同一seedの予測あり－予測なし | 15分遅れ予測を使うことによる変化 |
| R2 − R0 | 同一seedの予測付きJDRT－バスなし | 組合せ全体の変化。補助比較として扱う |

### 8.3 副指標

- Type3、Type4、全人口の避難完了数・率
- 未出発、立ち往生、閉鎖到達不能など理由別人数
- JDRT予約完了数、待ち時間の中央値・95%点・最大値
- JDRT総走行距離、空車距離、輸送人数、車両別稼働率
- 自家用車・送迎車等の出発、到着、未到着
- 全体の平均速度、停止台数、走行中台数
- 避難所別到着数、満員・代替移動数
- Type別・地域別の結果差

R0に存在しないJDRT待ち時間は0ではなく「該当なし」と記録する。

## 9. 周辺道路の混雑出力

新系列では、全体平均だけでなく道路区間別の観測を必須にする。

| 出力 | 最低限必要な内容 |
|---|---|
| 道路区間時系列 | 時刻、道路区間ID、平均速度、車両数、停止台数 |
| 閉鎖状態 | 道路区間ID、閉鎖時刻、観測時点の開閉 |
| 周辺区分 | 避難所周辺、JDRT通過道路、閉鎖地点周辺の該当フラグ |
| 地図表示用 | 道路形状との対応ID、時間帯別混雑階級 |

「避難所周辺」の距離、「停止」の速度基準、集計間隔はfull run前に固定する。結果を見た後で都合のよい範囲へ変更しない。

## 10. 感度分析

全因子の組合せは行わず、**一度に1項目だけ変更する**。

### 優先する3項目

1. JDRT利用率
2. 予約・避難開始時刻の分布
3. JDRT車両台数

### 次点の項目

- 乗車・降車時間
- 避難所容量・開設時刻
- 背景交通量
- 相乗り・再割当の有無

標準値、低条件、高条件などの具体値は根拠調査後に固定する。感度条件は中核結果を見る前に登録し、結果に応じた追加・削除を行わない。

中核15セルとは別に、感度セルは最大45セルを目安とし、新系列全体を原則60セル以内に収める。同じR0入力・設定・seedの完全一致がSHAで確認できる場合だけ、重複するR0セルを再利用できる。

## 12. 技術検証ゲート

各full runは少なくとも次を満たした場合だけ採用する。

- protocol・Parameter・全入力のSHA一致
- 人物、交通手段、予約、乗員、避難結果の保存則一致
- 同一人物の重複輸送0
- 車両定員超過0
- 実際の閉鎖情報が全条件で同一
- R1へTrue closure予測を渡さない
- R2へ登録済みの15分遅れ予測だけを渡す
- 未処理SUMO Error 0
- teleport、collision teleport、gridlock teleport 0
- 道路別混雑出力の時刻・道路ID欠損が許容基準内
- manifestと一次出力を上書きしない

技術不合格runは削除せず理由付きで保存する。結果の大小を理由に除外しない。seedの置換、設定変更、再実行が必要な場合は新しいversionとして全比較条件へ同じ変更を適用する。

## 13. 解釈規則

- 5seedが揃う前に方式の優劣を述べない。
- 単一runの値を政策効果として扱わない。
- 差なし、符号混在、逆方向も結果として採用する。
- R0の定義が仮定中心の場合、「現在の実態を再現した」と表現せず「設定した現在行動シナリオ」と呼ぶ。
- P1の完全予測は現実条件追加実験の中核に含めない。
- 既存Phase 3の固定経路バス結果と新JDRT結果を直接結合しない。
- 常総市の結果を他地域へそのまま一般化しない。

## 14. 所要時間と実行計画

JDRT v2有効14セルの実測では、通常12セルは14.9〜26.8分、seed 7の2セルは16.2〜17.1時間だった。このため、平均値だけでなく長時間化を含めて計画する。

| 作業 | 目安 |
|---|---:|
| 現在行動・運用データの棚卸しと数値判断 | 2〜5営業日 |
| PAP・Parameter Registry・入力仕様 | 1〜3営業日 |
| 実装・道路別出力・テスト・smoke | 3〜7営業日 |
| 中核15セル | 通常5〜8時間、長時間化込み2〜5日 |
| 中核評価・図表 | 2〜4営業日 |
| 優先感度分析 | 追加1〜2週間 |

中核結果までの全体目安は、必要データが揃っていれば2〜3週間とする。外部資料の取得、運行事業者への確認、避難所容量の欠損補完が必要な場合は3〜4週間以上を見込む。

## 15. 現時点で固定したこと・未確定のこと

### 固定したこと

- 現行v2を変更せず20/20まで完了する。
- 現実条件版は独立した新系列にする。
- R0、R1、R2の3条件で、導入効果と予測効果を分ける。
- 中核はpaired 5seed・15セルとする。
- 個人単位の交通手段対応と二重計上防止を必須にする。
- 道路区間別混雑を新系列の必須出力にする。
- 感度分析は一項目ずつ行い、全因子直積を行わない。
- 結果を見る前にPAP、パラメータ、感度、停止規則を固定する。

### 未確定で、REAL-P1/P2で決めること

- バスなし時の徒歩・送迎・従来救援・移動手段なしの割合
- JDRTの標準利用率
- 予約・自家用車出発の時間分布
- 実際に確保できる車両数、車種、待機場所
- 利用者別の乗降時間
- 避難所容量、開設時刻、代替先
- 背景交通に含める車両
- 周辺道路の範囲と道路別混雑の判定基準
- 感度分析の具体値と最終セル数

これらの未確定値を、既存値や便宜的な初期値から自動的に流用しない。
