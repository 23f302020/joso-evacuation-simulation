# 現実条件版：仮定シナリオ設計案 v1

> **2026-10-15ユーザー判断：圧縮閉鎖を使う第一案は不採用。実時間6時間・15分を評価できる洪水入力の再構築を先行する。以下は採用前の提案履歴として保全し、個々の仮定値も採用しない。** 現在の工程は[実時間再構築の方針・監査](../../02_情報調査/氾濫・浸水/jdrt_realtime_20261015/実時間洪水入力_再構築方針・取得監査.md)を参照。

作成：2026-10-15 JST。ユーザーが「A：仮定を明示した比較設計と不足資料の収集を並行（推奨）」を選択したため、具体的な条件を提示する。**本案の個々の数値・方法は採用前。正式PAP/Registry・実行設定ではない。** 実態を表す標準推定値の代わりに、何を仮定すると何が比較できるかを固定する提案である。

## 1. 今回の重要な追加確認：時間軸

既存`derived/time_mapping_sumo.csv`は2015/9/10 18:00〜9/16 10:20の閉鎖8時点を、sim789〜21,600秒へ圧縮している。最初の元経過18,600秒がsim789秒、最後509,400秒がsim21,600秒。概ね0.0424倍であり、**モデル6時間は実災害6時間の再現ではない**。sim900秒の予測誤差も実時間の15分と同じとは言えない。道路走行・乗降を同率で圧縮した実災害再現でもない。

第一案は、この圧縮閉鎖を保持して「現行運用資源を参照した条件付き比較」と明記する。目的は制約付き需要・供給・受入下の導入/予測比較であり、現実の6時間救出人数や実時間15分予測の効果を推計しない。実時間比較を必要とする代替案は、実時間の洪水閉鎖系列・対象時間窓を新たに用意する。既存8点の時間名だけ変更して代用しない。

この時計の選択は採用前に確認する。既承認方針の「6時間以内」「15分遅れ」の実用的な意味に影響するため、正式PAPで明示判断を必要とする。

## 2. 第一案の具体値・規則

以下はすべて3条件で共通にし、R0/R1とR1/R2で許可する差だけを変える。既存のv2・先行R0とは別protocol/出力先にする。原本の公表値を使う欄も災害時の成立保証とは扱わない。

## 3. セル順と感度の提案

第一段階は50%条件×R0/R1/R2×5seedの15セルを提案する。順序はseed23423→42→1→7→101の各seed内でR0→R1→R2。最初のR0を技術ゲートにし、不合格なら原因を記録し後続を止める。既存先行R0は新設定と異なるため転用しない。

第二段階候補は利用率25%・100%それぞれ同じ15セル、追加30セル。利用率を変えてもR0は同一だが、重複runは作らず、採用条件が完全一致する同一R0への参照で比較する方式を登録する。したがって3利用率の比較表は45セル相当、独立実行はR0 5＋R1/R2 30＝35run候補となる。主15セルの結果に合わせて感度を選ばない。第二段階を含めるかは実行前に固定し、全体完了前の方向主張をしない。

容量無制約、fleet3台、乗降180/600秒、非保有10/20%等をさらに追加することは本案に含めない。計算量を無制限に広げず、必要性を別判断する。35run候補も未承認であり自動開始しない。

## 4. 採用時に残すもの

本案の採否・修正点、圧縮時計の意味、一次根拠/仮定一覧、全条件表、共通人口と外生実現値の生成規則、上記の構造的停止規則を新PAPへ固定する。その後に新入力を生成・SHA固定し、独立会計・smoke・スキル新protocol対応を経て初めてrun可能とする。仮定案の採用だけを未検証実装の実行許可として扱わない。
