# 現状把握資料のデザイン維持・更新ガイド

制定：2026-10-22。別チャットでも、現在の見た目と操作を維持して内容を更新するための引継ぎ文書です。

## 1. 更新前に読むもの

1. [文章・記録ルール](現状把握_文章・記録ルール.md)：読者、文章、用語、記録する内容の基準。
2. 本文書：デザインを維持する範囲と更新手順。
3. [現在のHTML](現状把握_静的・動的シミュレーション整理.html)：実装の正本。配色や余白の実際の値は、このファイルの`<style>`を確認します。

通常の依頼が「経過を記録する」「現在地を更新する」「説明を追記する」であれば、現在のHTMLをそのまま使って内容だけを更新します。新しいデザイン案、別のページひな形、開発用の仕組みへの置換は行いません。ユーザーがデザイン変更を依頼した場合だけ、その対象を変更します。

## 2. 維持する見た目

以下は制定時の実装から確認した基準です。細かな指定や例外はHTML内のCSSを正本とし、この文書からCSS全体を再作成しません。

| 対象 | 維持する内容 |
|---|---|
| 全体 | 白地、濃い文字、青の強調色。大きな画像や装飾を追加しない |
| 基本色 | 文字`#1a1a1c`、補足`#4d4d4d`、青`#0017c1`、罫線`#c9c9c9`、状況欄の背景`#f1f6ff` |
| 本文 | 18px、行間1.75倍。書体は既存の日本語ゴシック体の指定を維持 |
| 見出し | 現在の文字サイズと段階を維持。本文の見出しは順序を飛ばさない |
| 幅と余白 | 内容の最大幅1040px。PCは左右32px、画面幅640px以下は左右16pxを確保 |
| 冒頭 | ページ名・説明に続いて、確認時刻付きの現在状況を青い左罫線の欄で表示 |
| 表 | 薄い灰色の見出し行と横罫線。スマートフォンでは表の枠内で横にスクロールできる |
| 日付別の経過 | 日付と短い概要を並べ、詳細を開閉。新しい日付を上に置き、最新日だけ初期状態で開く |
| 詳細情報 | 運転担当者向けの情報は補足の開閉欄。現在状況と重要な限界は折りたたまない |
| 操作 | リンクの下線、キーボード操作時の黒い輪郭と黄色い背景、本文への移動、ページ先頭へ戻る操作を維持 |

デジタル庁デザインシステムの指針を参考にした、この研究向けの実装です。公式サイトの更新を理由に、このページの外観を自動で変えません。出典・加工した旨の表示も保持します。

## 3. 変更する場所

| 更新内容 | 変更先と方法 |
|---|---|
| 日付別の経過 | Markdownの`PROGRESS_LOG_BEGIN/END`内へ、日付見出しと短い箇条書きを追加。既存のHTML反映処理を使う |
| 現在状況 | 既存の`choice_sync_status.py`による確認・表示同期を使う。実行回数や採用数を推測で手入力しない |
| 研究の説明 | Markdownを先に更新し、対応する既存HTMLの節の文章・表へ同じ内容を反映 |
| 新しい説明項目 | 既存の見出し・段落・表・補足欄の形を再利用。新しい見た目の部品を増やす前に既存の形で表せるか確認 |

`<style>`、末尾の`<script>`、既存の節の`id`・クラス名、`CHOICE_CURRENT_*`と`PROGRESS_*`の更新範囲、`choice_record`の正式記録マーカーは通常の内容更新では変更しません。節の識別名はページ内リンクにも使っています。文書全体の再生成や`gen_index.py`は使いません。

実験の採用条件・記録方法は研究側の規則に従います。表示のために固定された実験プログラムを変更したり、正式記録を手作業で代用したりしません。

## 4. 更新後の確認

1. 対象差分で、依頼した文章・数値・経過だけが変わっていることを確認します。通常の内容更新ではCSSと操作用JavaScriptの差分がないことも確認します。
2. 日付別記録はプロジェクトのPythonで`status_progress.py --apply`を実行し、`--check`でMarkdownとHTMLの一致を確認します。正式記録と同じ書込ロックを尊重し、ロックを削除して進めません。
3. リンク、見出し、数値の対象・単位・時点、正式記録マーカーを確認し、`git diff --check`を実行します。
4. 文章量や表の構成を変えた場合は、PC・スマートフォンで見切れや重なりがないことを確認します。制定時の確認幅は1440pxと390pxです。開閉や操作を変えた場合はマウス・キーボードでも確認します。

元の画面・文章ルールと判断に迷う差があれば、独自にデザインを作り直さず、差の理由を確認します。内容更新だけで公開・commit/pushまで許可されたとは扱いません。

## 5. 引継ぎ時の短い指示

> 現状把握資料は、文章・記録ルールとデザイン維持・更新ガイドを読んでから更新してください。現在のHTMLを使い、通常は文章・表の内容・日付別記録だけを変更します。CSS・操作用JavaScript・節の識別名・更新範囲・正式記録マーカーを保ち、既存の同期処理と確認手順を使ってください。
