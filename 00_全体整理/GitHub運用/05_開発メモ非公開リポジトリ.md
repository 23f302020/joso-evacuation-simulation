## 2. 公開リポジトリとの違い

| 項目 | 公開 `joso-evacuation-simulation` | 非公開 `joso-evacuation-devnotes` |

## 3. 基本ルール

1. **非公開を維持する。** 公開設定の変更、Pages・公開用Actionsの有効化、外部への共有リンクの作成をしない。
2. **2つのリポジトリを混ぜない。**
   - `開発メモ/`の中で公開リポジトリのremoteを登録しない。公開リポジトリ側で`開発メモ/`を追跡しない（`.gitignore`は変更しない）。
   - 開発メモの本文を、公開リポジトリのファイルへ丸ごと転記しない。公開文書から参照するときはパス名だけにする。
3. **コマンドは必ず`開発メモ/`の中で実行する。** 親フォルダで実行すると公開リポジトリが対象になる。実行前に`git remote get-url origin`で、操作対象が`joso-evacuation-devnotes`であることを確かめる。
4. **履歴を書き換えない。** force push・`rebase`・`reset --hard`・`commit --amend`（push済みのもの）をしない。
5. **秘密情報を書かない。** APIキー・トークン・パスワードは開発メモにも書かない（非公開でも、誤って公開されたときの被害を防ぐ）。
6. **編集はメインPCだけで行う。** 学校PCにはrobocopyで`.git`ごと複製されるが、読むだけにし、そこではcommit・pushしない。

## 4. commitとpushのタイミング

| 場面 | 対応 |
|---|---|
| 開発メモに研究判断・監査・決定を書いた／直した | その作業の区切りでcommitする。commitはローカルの記録で、外部へは送らない |
| push | **ユーザーの明示依頼があるときだけ**（公開リポジトリと同じ原則）。ただし、ユーザーが「開発メモも保全して」等、保全を含む依頼をした場合は、その依頼の範囲でpushしてよい |
| 公開リポジトリへpushするとき | 開発メモに未commit・未pushの変更があれば、ユーザーに伝える（片方だけ保全されている状態を放置しない） |

commitメッセージは[02 §3](02_ブランチとコミット.md#3-コミットメッセージ書式)の書式に従う。本文には、どの判断・決定番号の記録かを書く。

```powershell

# 23f302020 のトークンをこのプロセスの間だけ使う（画面に出さない）

  gh api repos/23f302020/joso-evacuation-devnotes --jq .visibility    # private を確認
  git -c credential.helper= -c "credential.helper=!gh auth git-credential" push origin main
} finally {
  Remove-Item Env:GH_TOKEN -ErrorAction SilentlyContinue
}
```

## 7. push後の読み戻し確認

```powershell
git rev-parse HEAD
$env:GH_TOKEN = (gh auth token --user 23f302020)
try {
  git -c credential.helper= -c "credential.helper=!gh auth git-credential" ls-remote origin refs/heads/main
  gh api repos/23f302020/joso-evacuation-devnotes --jq .visibility
} finally { Remove-Item Env:GH_TOKEN -ErrorAction SilentlyContinue }
gh api user --jq .login             # JI-life のまま（グローバル状態を変えていない）
```

- ローカルの`HEAD`とGitHubの`main`のSHAが一致し、`private`であることを確認する。
- 完了報告には「開発メモ：ローカルcommitのみ／非公開GitHub反映済み」を区別して書く。

## 8. 学校PC・複数PC

- 学校PCへは、研究フォルダの丸ごと複製（robocopy）で`開発メモ/.git`も一緒に複製される。
- 学校PCでは読むだけにする。学校PCに23f302020の認証を置く必要はない。
- 学校PCで開発メモを直す必要が出た場合は、メインPCで直してから複製し直す。2台で別々にcommitした場合は、自分で合流させずユーザーに報告する。

## 9. トラブル対応

| 事象 | 対応 |
|---|---|
| 公開設定がpublicになっていた | **すぐ止めて**ユーザーに報告する。privateへ戻すのはユーザーの判断で行い、公開されていた期間と、その間に秘密情報が無かったかを記録する |
| 公開リポジトリに開発メモの内容が入ってしまった | pushしていなければ、そのコミットから外して作り直す。push済みなら履歴の書換えが必要になるため、自分で行わずユーザーに報告する（[04](04_トラブル対応.md)の原則） |
| 親フォルダで誤ってコマンドを実行した | 公開リポジトリの状態（`git status`）を確認し、意図しない変更を報告する。`git restore`は使わない（恒久禁止事項3） |
| remoteの登録を間違えた | `git remote -v`で確認し、`git remote set-url origin https://github.com/23f302020/joso-evacuation-devnotes.git`で直す。誤った先へpush済みなら止めて報告する |
| pushが403で拒否される | [04](04_トラブル対応.md#push-が-403-で拒否される)と同じ（JI-lifeの資格情報が使われている可能性） |
| `開発メモ/`内の`.git`が消えた／壊れた | 再作成せず、GitHub側を正として、別フォルダへcloneして差分を確認してからユーザーに報告する |
