# 01 公開範囲と除外ルール

> リポジトリは**public**である。pushしたものは誰でも閲覧・複製でき、後で消しても取得済みの複製やキャッシュは残る。
> 公開範囲の正本は`.gitignore`。本書はその意図と運用を説明する。

---

## 1. 載せるもの

| 区分 | 例 |
|---|---|
| 研究文書 | `00_全体整理/`・`02_情報調査/`（PDF除く）・`03_研究設計文書/`・`05_タスク管理/`・`06_研究結果/`のMarkdown |
| 実装・テスト | `04_プログラム/scripts/`・`04_プログラム/tests/`・`.agents/skills/` |
| 公開ビューア・集計結果 | `04_プログラム/output/`のうちHTML/CSS/JS/JSON/CSV/MDと研究図SVG（allow-list方式） |
| 入力データの再現情報 | `04_プログラム/data/README.md`・`manifest.csv`（生データ本体は載せない） |
| アーカイブの概要 | `07_アーカイブ/**/README.md`のみ |
| 最新の発表資料 | `01_経過報告/発表資料/`の最新版フォルダのみ |

## 2. 載せないもの

| 区分 | 理由 | `.gitignore`上の扱い |
|---|---|---|
| `開発メモ/` | 方針判断の正本・監査記録はローカル運用（保全はOneDrive版数履歴） | `開発メモ/` |
| `04_プログラム/data/**` | 再ダウンロード可能。README/manifestで再現 | allow-list以外除外 |
| `output/`の中間生成物・大容量 | `.xml`・`.net.xml`・`.rou.xml`・`.gpkg`・`.pkl`・画像・`network/`等 | 拡張子単位で除外 |
| `07_アーカイブ/`の実体（約3.74GB） | 容量・端末固有の絶対パスを含むmanifest | README以外除外 |
| 外部取得の原本 | 再配布しない（USACE展開物、jdrt_realtime raw、`02_情報調査/**/*.pdf`） | パス指定で除外 |
| 依存・キャッシュ | `venv/`・`__pycache__/`・osmnx cache・`.wrangler/`・`node_modules`リンク | 除外 |
| 旧版の発表資料・参考資料 | 最新版だけ追跡 | フォルダ指定で除外 |
| 秘密情報 | APIキー・トークン・パスワード | **ファイル自体を作業ツリーに置かない**。APIキーはリポジトリ外の`研究室/公共交通オープンデータ/` |
| 私的な参照記録 | 私的Drive参照記録、raw console capture | コミット対象に含めない（都度確認） |

## 3. `.gitignore`を変更するとき

1. 変更理由（新しく載せる／外すもの）を決める。
2. 編集後、意図した結果になったかを確認する。

   ```powershell
   git status --short --ignored -- <対象パス>
   git check-ignore -v <対象ファイル>
   ```

3. **既に追跡済みのファイルは`.gitignore`に足しても外れない。** 公開をやめるなら`git rm --cached <path>`で追跡だけ外す（ローカルの実体は残る）。過去のコミットには残る点をユーザーへ伝える。
4. コミット本文に「何を公開範囲に入れた／外したか」を書く。

### 発表資料のバージョン更新

新しい`verNN`フォルダを作ったら、`.gitignore`の除外リストから新版を外し、旧版を追加する（`01_経過報告/README.md`の規定）。

## 4. 新しい種類のファイルを追加するとき

- 拡張子・場所が既存のallow-listに入るかを`git status`で確認する。意図せず未追跡のまま残っていないか、逆に巨大ファイルが入っていないかを見る。
- 50MBを超えるファイルはGitHubが警告し、100MBを超えると拒否される。研究データは原則載せず、README/manifestで再現手順を残す。
- Git LFSは使っていない。導入する場合はユーザー判断とする。

## 5. 改行コード

- `.gitattributes`は`*.py text eol=lf`のみ。他のファイルは改行を変換しない。
- 確定routeなどCRLFのままSHAを固定している成果物があるため、`git restore`や`git checkout -- output/`、一括の改行正規化（`git add --renormalize`）を行わない。
